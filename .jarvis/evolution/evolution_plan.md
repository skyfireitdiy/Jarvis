# Jarvis 自进化与智能增强计划（重写版 v2.0）

## 概述

本计划定义 Jarvis 从代码助手向主动、自主的智能系统演进的路径。

**核心使命**：将 Jarvis 打造成一个**高效、主动、越用越聪明**的智能助手，为 skyfire 提供高效、智能的支持。

**执行原则**（遵循自进化规则）：

- **效率绝对优先**：一切进化以「提升效率」为第一目标，不堆砌无实际价值的功能。
- **skyfire 利益优先**：每个决策以最大化 skyfire 利益为准。
- **可验证、可回滚**：每个阶段有明确验收标准，有测试验证，有 Git 提交，可回退。
- **完整记录**：进化活动记录至 `.jarvis/evolution/`。
- **基于事实**：本计划基于 2026-10-04 对系统现状的全面盘点，区分「已实现」与「规划中」。

## 新阶段规划（效率优先）

> 设计原则：**不做「为功能而功能」的事**。每个阶段聚焦一个能直接提升效率的闭环能力，轻量、可验证、不引入重依赖。

### 阶段 A：自我进化闭环（当前最优先）

**目标**：让 Jarvis 形成「需求澄清 → 主动建议 → 跨会话学习」的闭环，越用越聪明、越用越高效。

**预计时间**：2026-10 起，约 4-6 周

#### A1. 需求澄清与意图理解（P0）

- **现状**：任务描述含糊时直接按字面执行，易做偏、返工。
- **要做**：
  - 动手前识别「需求是否明确」，含糊时主动澄清（一问一答，不啰嗦）。
  - 识别任务类型（代码/文档/分析/运维等），选择对应执行策略。
- **验收**：含糊需求下，澄清后再执行的比例显著提升；返工率下降。

#### A2. 主动服务 / 主动建议（P0）

- **现状**：完全被动，问一句答一句。
- **要做**：
  - 任务完成后主动给出「下一步建议」。
  - 发现用户反复做同一类事时，主动提醒「是否沉淀为方法论/工具」。
- **验收**：任务完成后能给出有依据的下一步建议；重复劳动被自动识别并提示沉淀。

#### A3. 跨会话持续学习（P0）

- **现状**：有 memory 工具，但主要靠模型「自觉」保存，缺少主动检索复用机制。
- **要做**：
  - 任务开始前自动检索相关历史经验，注入上下文。
  - 任务结束后自动判断「踩的坑/用的方法是否值得沉淀」，主动沉淀。
- **验收**：同类任务第二次执行时能自动复用上次经验，效率可量化提升。

#### A4. 进化状态修正（P0 前置）

- **要做**：修正 current_phase.md 中与事实不符的「已完成」标记，如实反映进度。
- **验收**：进化状态文档与源码事实一致。

### 阶段 B：效率增强能力（按需补充）

**目标**：在核心闭环稳定后，补充真正缺失、能直接提升特定场景效率的小能力。

**预计时间**：阶段 A 完成后，按需启动

#### B1. 代码复杂度 / 重复度分析（小补丁）

- **现状**：`code_analyzer` 已覆盖依赖分析、影响分析、符号表、图遍历，但缺「圈复杂度/认知复杂度、代码重复度」两个小能力。
- **要做**：在现有 `code_analyzer` 上补充这两个分析，作为轻量增量，不建独立大模块。
- **验收**：能对指定文件/项目输出复杂度与重复度报告。

#### B2. 自动测试生成

- 根据代码改动自动生成测试用例，减少手工写测试时间。

#### B3. 文档自动生成

- 根据代码/API 自动生成文档，省去大量写文档时间。

### 阶段 C：远期能力（成本高，按需启动）

**目标**：在核心效率能力稳固后，探索更高阶能力。**不盲目启动，需 skyfire 明确授权。**

> 注：经复核，旧计划中的「架构分析、自动修复、知识图谱、智能顾问」多数已被现有模块覆盖，**不再列入**。以下仅为真正未覆盖且成本高的远期项。

#### C1. 语音 / 多模态交互

- 成本高，对代码助手场景提升有限。**后置**。

#### C2. 创造性思维 / 情感理解

- 阶段4远期目标，当前投入产出比低。**后置**。

#### C3. 业务级知识图谱（经验/记忆关系化）

- 代码级符号图谱已有；若需把记忆、方法论组织成业务关系图谱再评估。**后置**。

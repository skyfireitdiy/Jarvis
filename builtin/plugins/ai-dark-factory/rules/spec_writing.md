# NLSpec 编写规范

## 什么是 NLSpec

NLSpec（Natural Language Spec，自然语言规格）是 AI 黑灯工厂流水线的**输入**。它是一份带形式化约束的结构化英文描述，精确到编码 agent 无法用判断填补空白。

黑灯工厂的原则是：**Specs 进，可工作的软件出**。spec 的质量直接决定产出质量——模糊的 spec 会失败，清晰的 spec 会成功。

## 四要素（缺一不可）

一份合格的 NLSpec 必须包含以下四部分：

1. **Goal（目标）**：要构建什么。用一句话说清功能与价值。
2. **Constraints（约束）**：硬性限制。技术栈、性能指标、安全要求、兼容性、不可用方案。**约束必须显式**——agent 不能靠判断填补空白。
3. **Interfaces（接口）**：对外契约。函数签名、API 端点、数据结构、输入输出格式、错误语义。
4. **Non-goals（非目标）**：明确**不做什么**。防止 agent 过度设计或越界实现。

## 编写原则

- **约束显式化**：把隐含假设全部写出来。例如"加 auth"太模糊，应写成"加 OAuth2 PKCE 流程，带这 5 个约束"。
- **一个功能一个 spec**：巨型 spec 会压垮上下文窗口。每个 spec 聚焦单一功能，保持可独立评估。
- **可验证**：每个 Goal 都应能通过某种验收场景验证。无法验证的目标等于没有目标。
- **接口精确**：接口定义到参数类型、返回结构、错误码级别，让生成器无需猜测。
- **Non-goals 明确**：明确边界，防止 agent 为实现额外功能而偏离主线。

## 常见失败模式

- **模糊的 spec**：agent 无法推断意图，产出泛化代码。
- **巨型 spec**：压垮上下文窗口，导致遗漏与不一致。
- **约束缺失**：agent 用判断填补空白，做出错误的技术选型。
- **无验收标准**：无法评估产出是否达标。

## 与工具配合

编写 spec 后，用 `spec_validator` 工具校验是否含四要素；用 `holdout_generator` 工具生成隐藏验收场景（编码 agent 不可见）。

# TDD 铁律

## 核心原则

**无失败测试不写代码**。这是黑灯工厂生成器的铁律——先写测试，再写实现，直到测试通过。

TDD 保证产出可验证，是隔离评估器能客观评估产出的前提。没有测试的代码无法评估，也就无法通过门禁。

## 纪律要求

1. **先写测试**：任何功能实现前，先编写能验证该功能的测试。
2. **红-绿-重构**：先看到测试失败（红），再写实现让它通过（绿），最后重构（保持测试绿）。
3. **测试即契约**：测试定义了接口的预期行为，是接口契约的可执行形式。
4. **不跳过**：没有失败测试就写代码，视为违规。

## 在流水线中的位置

```text
planner 拆解任务
  → generator 先写测试（红）
  → generator 写实现（绿）
  → validator 用 holdout scenarios 独立评估
  → orchestrator 汇总报告 → 人工审批关口
```

## 与 holdout scenarios 的关系

- **TDD 测试**：生成器自己写的、可见的单元/集成测试——用于驱动实现。
- **Holdout scenarios**：评估器持有的、编码 agent 不可见的隐藏验收场景——用于独立评估。

两者互补：TDD 驱动正确实现，holdout 验证真实达标。

## 常见陷阱

- **跳过测试**：直接写实现，产出无法验证。
- **测试太弱**：只测 happy path，不测边界与异常。
- **测试与实现同构**：测试只是复述实现逻辑，没有独立价值。
- **为通过而测试**：让测试迁就实现而非实现满足测试。

## 与工具配合

生成器编写 spec 驱动的测试时，参考 `spec_writing` 规则确保 spec 四要素清晰；评估阶段用 `gate_calculator` 工具计算门禁通过率。

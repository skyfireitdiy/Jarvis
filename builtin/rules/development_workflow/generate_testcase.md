# 文本化测试用例生成规则

## 规则简介

本规则指导如何基于项目需求文档与代码接口，生成结构化之文本化测试用例，以指导后续集成测试开发。所生成之测试用例文件将写入 `.jarvis/rules/spec/test_cases.md`。

## 汝必遵守之原则

### 1. 需求驱动原则

**要求说明：**

- **必**：优先读取 `.jarvis/rules/spec/` 目录下之Spec文件作为需求来源
- **必**：基于Spec中所定义之功能行为与验收标准设计测试用例
- **必**：每验收标准至少对应一测试用例
- **禁**：脱离需求文档臆测测试场景
- **禁**：遗漏Spec中所定义之边界条件与异常处理

### 2. 用例完整性原则

**要求说明：**

- **必**：覆盖功能测试（正常流程）
- **必**：覆盖边界条件测试（空值、极值、临界值）
- **必**：覆盖异常处理测试（错误输入、异常状态）
- **必**：覆盖接口兼容性测试（参数类型、返回值格式）
- **禁**：只覆盖正常流程而忽略异常场景

### 3. 用例结构化原则

**要求说明：**

- **必**：每用例含：用例编号、用例名称、前置条件、测试步骤、预期结果、优先级
- **必**：按功能模块分组组织测试用例
- **必**：优先级用 P0（核心功能）、P1（重要功能）、P2（辅助功能）三级分类
- **必**：用例编号格式为 `TC-{模块缩写}-{序号}`（如 TC-AUTH-001）
- **禁**：用模糊之预期结果（如"正常返回"、"不出错"）

## 汝必执行之操作

### 操作1：收集需求信息

**执行步骤：**

1. 读取 `.jarvis/rules/spec/` 目录下之所有Spec文件
2. 提取每Spec之功能概述、接口定义、功能行为与验收标准
3. 若无Spec文件，则分析源码中之接口定义与文档字符串

### 操作2：分析代码接口

**执行步骤：**

1. 浏览源码目录，识别公共接口（函数、类、API端点）
2. 读取接口之参数定义、返回值类型与文档字符串
3. 识别接口间之调用关系与依赖

### 操作3：设计测试用例

**执行步骤：**

1. 根据Spec之验收标准，为每功能点设计正常流程用例
2. 根据边界条件，设计边界值测试用例
3. 根据异常处理说明，设计异常场景用例
4. 根据接口定义，设计接口兼容性用例
5. 为每用例分配优先级（P0/P1/P2）

### 操作4：生成测试用例文件

**执行步骤：**

1. 按功能模块分组组织测试用例
2. 用 `edit_file` 工具将测试用例写入 `.jarvis/rules/spec/test_cases.md`
3. 确保每用例结构完整、预期结果明确

### 测试用例文件模板

```markdown
# 测试用例文档

## 模块：[模块名称]

### [模块名称] 功能测试

| 用例编号     | 用例名称   | 前置条件   | 测试步骤                 | 预期结果       | 优先级 |
| ------------ | ---------- | ---------- | ------------------------ | -------------- | ------ |
| TC-{MOD}-001 | [用例名称] | [前置条件] | 1. [步骤1]<br>2. [步骤2] | [具体预期结果] | P0     |

### [模块名称] 边界条件测试

| 用例编号      | 用例名称   | 前置条件   | 测试步骤   | 预期结果       | 优先级 |
| ------------- | ---------- | ---------- | ---------- | -------------- | ------ |
| TC-{MOD}-B001 | [用例名称] | [前置条件] | 1. [步骤1] | [具体预期结果] | P1     |

### [模块名称] 异常处理测试

| 用例编号      | 用例名称   | 前置条件   | 测试步骤   | 预期结果       | 优先级 |
| ------------- | ---------- | ---------- | ---------- | -------------- | ------ |
```

## 检查清单

完成任务后，汝必确认：

- [ ] 已读取所有Spec文件并提取需求
- [ ] 已分析代码接口定义
- [ ] 每验收标准至少对应一测试用例
- [ ] 覆盖功能测试、边界条件、异常处理、接口兼容性
- [ ] 每用例含完整结构（编号、名称、前置条件、步骤、预期结果、优先级）
- [ ] 用例按功能模块分组组织
- [ ] 测试用例文件已写入 `.jarvis/rules/spec/test_cases.md`
- [ ] 预期结果具体明确，可验证

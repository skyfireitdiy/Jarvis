# 重构规则

## 汝必遵守之重构原则

### 1. 小步快跑原则（必遵守）

**执行要求：**

- **必**：每次重构只做小之改动
- **必**：每次改动后立即运行测试
- **必**：确认测试通过后再进行下一步重构
- **必**：用版本控制，每次小改动都提交，便于回滚

**禁行：**

- **禁**：一次性进行大规模重构
- **禁**：在测试未通过之情况下继续重构

### 2. 保持功能不变原则（必遵守）

**执行要求：**

- **必**：重构不应该改变代码之外部行为
- **必**：重构前后，全测试必都能通过
- **必**：若有功能变更需求，必单独提交，不要与重构混在一起

**验证方法：**

- 重构前运行全测试，记录测试结果
- 重构后运行全测试，确保结果一致
- 若测试失败，立即回滚或修复

### 3. 识别代码异味（必识别并处理）

**汝必识别并处理之代码异味：**

- [ ] 重复代码（违反 DRY 原则）
- [ ] 过长之方法或类（超过合理长度）
- [ ] 过深之嵌套（超过 3-4 层）
- [ ] 魔法数字和字符串（未命名之常量）
- [ ] 过度之参数列表（超过 3-4 个参数）
- [ ] 过长之方法链
- [ ] 过大之类（职责过多）

## 汝必掌握之重构技巧

### 1. 提取方法（Extract Method）

**何时用：** 方法过长或含重复逻辑
**操作步骤：**

1. 识别可以独立之方法块
2. 创建新方法，移动代码
3. 用方法调用替换原代码
4. 运行测试确认

### 2. 提取变量（Extract Variable）

**何时用：** 复杂表达式难以理解
**操作步骤：**

1. 识别复杂表达式
2. 创建有意义之变量名
3. 用变量替换表达式
4. 运行测试确认

### 3. 重命名（Rename）

**何时用：** 名称不清晰或误导
**操作步骤：**

1. 确定更清晰之名称
2. 用 IDE 之重构工具进行重命名
3. 运行测试确认

### 4. 消除重复（Remove Duplication）

**何时用：** 发现重复代码
**操作步骤：**

1. 识别重复模式
2. 提取公共逻辑到函数或类
3. 替换全重复代码
4. 运行测试确认

### 5. 简化条件（Simplify Conditional）

**何时用：** 条件表达式复杂难懂
**操作步骤：**

1. 提取条件到有意义之变量
2. 用早期返回减少嵌套
3. 用更清晰之条件表达式
4. 运行测试确认

### 6. 移动代码（Move Code）

**何时用：** 代码位置不合适
**操作步骤：**

1. 确定代码应该存在之位置
2. 移动代码到合适位置
3. 更新引用
4. 运行测试确认

## 重构时机判断

### 汝必进行重构之情况

1. **添加新功能前**：
   - 若现有代码结构难以扩展
   - **必**：先重构现有代码，使其更容易扩展
   - **然后**：再添加新功能

2. **修复 Bug 时**：
   - 若发现代码结构有问题导致 Bug
   - **必**：先重构代码结构
   - **然后**：再修复 Bug

3. **代码审查时**：
   - 若发现可以改进之地方
   - **必**：建议重构
   - **必**：提供具体之重构建议

4. **定期清理**：
   - **必**：定期进行技术债务清理
   - **必**：识别并重构代码异味

## 重构执行检查清单

在完成重构后，汝必确认：

- [ ] 全测试都能通过（重构前后测试结果一致）
- [ ] 代码更清晰、更易读
- [ ] 没有引入新之 bug
- [ ] 性能没有明显下降（如有下降，必说明原因）
- [ ] 代码更易于扩展和维护
- [ ] 代码异味已消除或减少
- [ ] 重构已提交到版本控制

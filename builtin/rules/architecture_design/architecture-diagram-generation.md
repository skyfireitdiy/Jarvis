# 架构图生成之规

## 汝必循之工作流程

### 架构图生成完整流程（严循）

1. **需求澄清阶段**:
   - 必明用户需生何种架构视图
   - 禁于需求不明时始代码分析

2. **代码阅读阶段**:
   - 必用 `read_code` 工具完整细读用户所供之全部源码
   - 禁只读部分代码或凭空猜测

3. **组件识别与关系分析阶段**:
   - 必识核心类、模块、接口与函数
   - 必析其间之依赖、继承、调用与数据流关系
   - 必据视图类型，对组件行适当之抽象与分组

4. **视图绘制阶段 (DOT语言)**:
   - **逻辑视图**: 必关注功能与系统结构，主呈分层关系，避组件间连线过密
   - **实现视图**: 必关注代码之物理组织，示文件、模块、包及其依赖关系
   - **进程视图**: 必关注系统之运行时行为，示主要进程、线程、任务及其通信
   - **部署视图**: 必关注系统之物理部署，示硬件节点、网络连接及节点上部署之软件组件
   - **用例视图**: 必关注用户与系统之交互，示参与者与用例

5. **图表生成与渲染阶段**:
   - 必将所生Graphviz DOT代码输出至以`.dot`为后缀之文件中
   - 必用`execute_script`工具调`dot`令将`.dot`文件渲染为`.png`图片
   - 必向用户报告渲染后之图片路径

## 汝必守之原则

### 代码完整性原则

- **禁**：只读部分代码或凭空猜测系统架构
- **必**：完整细读并分析用户所供之全部源码
- **必**：准确识核心类、模块、接口与函数及其相互关系

### 视图准确性原则

- **必**：图表必准确反映代码之实际结构
- **必**：同系列图表中，相同组件之表示当保持一致
- **禁**：于图表中体现具体实现名称或路径，必用抽象之职责或角色命名

### 图表清晰性与视觉美感原则

- **必**：图表必简单明了，易于理解，具专业外观
- **必**：避组件间连线过密，保图表清晰，留白充足
- **必**：用协调统一之配色方案，不同层级用不同色系，确保视觉层次分明
- **必**：节点样式统一（圆角矩形、填充色、边框色），提升整体美观
- **必**：字体大小适中，标签文字清晰可读，避文字重叠或过小
- **必**：连线样式统一，用合适之箭头样式与线条粗细，重要关系可加粗显示
- **必**：子图（cluster）用柔和之背景色与清晰之边框，增强分组视觉效果
- **必**：整体布局平衡，节点分布均匀，避局部过于拥挤或稀疏

### 专业性原则

- **必**：严循架构设计与Graphviz之最佳实践
- **必**：所有输出之DOT代码必为完整、可直接渲染者
- **必**：含于 `digraph G { ... }` 中，循统一之样式规范

## 具体要求与规范

- 所有输出之DOT代码必为完整、可直接渲染者。
- 必含于 `digraph G { ... }` 中。
- **布局方向**: 层次结构明显之图（如组织架构、调用链），
  当优先用 `rankdir="TB"` 实现自上而下之布局。流程或序列
  关系，`rankdir="LR"`（从左至右）或更合适。
- **布局对齐**: 为获规整对齐之布局，请积极用
  `subgraph cluster_...` 对节点分组，并用
  `{ rank=same; ... }` 语句将需水平对齐之节点放于同一层级。
- **布局间距**: 为避免节点或文字重叠，可于 `graph [...]`
  中设 `nodesep` 与 `ranksep` 属性以增节点与层级间距，
  如 `nodesep=0.6, ranksep=1.0`。同时可设 `overlap=false` 禁
  重叠。
- 用graph、node与edge属性美化图表。推荐用以下专业且美观之样式规范：

```dot
digraph G {
    // --- Global Settings ---
    // 使用专业的全局样式设置，确保图表美观统一
    graph [rankdir="TB",
           splines=ortho,                    // 使用正交连线，更专业
           fontname="Sans-serif",
           fontsize=11,                      // 合适的字体大小
           label="图表标题：[在此处填写视图名称]",
           labelloc="t",
           fontcolor="#333333",              // 标题文字颜色
           newrank=true,
           nodesep=0.8,                      // 节点间距，避免拥挤
           ranksep=1.2,                      // 层级间距，层次分明
           overlap=false,                    // 禁止重叠
           bgcolor="#FFFFFF",                // 背景色为白色
           pad=0.5];                         // 边距，留白充足

    // --- Default Node Style ---
    // 默认节点样式：圆角矩形，柔和填充，清晰边框
    node [shape=box,
          style="rounded,filled",
          fillcolor="#F5F5F5",               // 浅灰填充，柔和舒适
          color="#666666",                    // 深灰边框，清晰不突兀
          fontname="Sans-serif",
          fontsize=10,
          fontcolor="#333333",                // 文字颜色，确保可读性
          penwidth=1.5];                      // 边框粗细适中

    // --- Default Edge Style ---
    // 默认连线样式：清晰简洁
    edge [fontname="Sans-serif",
          fontsize=9,
          fontcolor="#555555",                // 标签文字颜色
          color="#888888",                    // 连线颜色，不抢夺注意力
          penwidth=1.2,                       // 连线粗细
          arrowsize=0.8];                     // 箭头大小适中

    // --- Interface/Entry Point Nodes ---
    // 接口层/入口节点：使用醒目的暖色调
    node [group=interface,
          shape=cds,                         // 圆角矩形，表示接口
          fillcolor="#FFE6CC",               // 温暖的橙色填充
          color="#D79B00",                    // 深橙色边框
          penwidth=2.0];                      // 稍粗的边框，突出重要性
    api_gateway [label="API网关"];

    // --- Service Layer Subgraph ---
    // 服务层子图：使用专业的蓝色系，清晰分组
    subgraph cluster_services {
        label = "业务服务层";
        style = "filled,rounded";            // 填充+圆角，更美观
        fillcolor="#F0F4F8",                 // 浅蓝灰背景，柔和专业
        color="#6C8EBF",                      // 蓝色边框，与节点呼应
        fontname="Sans-serif";
        fontsize=11;
        fontcolor="#4A5568";                  // 深灰文字，清晰可读
        penwidth=2.0;                         // 边框稍粗，突出分组

        node [group=service,
              fillcolor="#DAE8FC",            // 浅蓝色填充
              color="#6C8EBF",                // 蓝色边框
              penwidth=1.8];                  // 边框粗细
        service_A [label="服务A"];
        service_B [label="服务B"];
    }

    // --- Data Layer ---
    // 数据层：使用绿色系，表示存储和持久化
    node [group=database,
          shape=cylinder,                      // 圆柱形，表示数据库
          fillcolor="#D5E8D4",                // 浅绿色填充
          color="#82B366",                    // 深绿色边框
          penwidth=2.0];                      // 边框稍粗，突出重要性
    database_A [label="数据库"];

    // --- Relationships ---
    // 关系连线：使用清晰的标签和样式
    api_gateway -> service_A [label="路由",
                               color="#6C8EBF",    // 使用服务层颜色
                               penwidth=1.5];
    api_gateway -> service_B [label="路由",
                               color="#6C8EBF",
                               penwidth=1.5];
    service_A -> database_A [label="读写",
                             color="#82B366",     // 使用数据层颜色
                             penwidth=1.5];
    service_B -> database_A [label="读",
                             color="#82B366",
                             penwidth=1.5,
                             style="dashed"];      // 只读关系使用虚线

    // --- Horizontal Alignment ---
    // 水平对齐：确保同级节点在同一水平线上
    { rank=same; service_A; service_B; }
}
```

**样式美化要点**：

- **配色方案**：用协调之色系，接口层用暖色（橙/黄），服务层用冷色（蓝），数据层用绿，外部系统用紫
- **字体规范**：统一用 Sans-serif 字体，标题11pt，节点标签10pt，连线标签9pt
- **边框样式**：重要节点用稍粗边框（penwidth=2.0），普通节点1.5-1.8
- **填充效果**：用柔和之浅色填充，避过于鲜艳，确保专业感
- **连线样式**：重要关系用实线加粗，次要关系用虚线，不同层级用对应颜色
- **子图美化**：用圆角填充背景（style="filled,rounded"），柔和之背景色，清晰之边框
- **留白设计**：通过 nodesep 与 ranksep 控间距，pad 控边距，确保图表不拥挤

- 据不同之视图，用合适之形状与样式。
- 模块节点尽量用矩形（shape=box）；除数据库、外部系统、消息队列等特殊组件外，避用他形表示"模块"。
- 抽象命名规范：勿于图中体现具体实现名称或路径（如 utils.output、xxx.py、具体函数名），用抽象之职责或角色命名（如输出模块、存储模块、网络层、鉴权服务）。
- 注释清晰，释图中之关键元素与关系。
- **准确性**: 图表必准确反映代码之实际结构。
- **清晰性**: 图表必简单明了，易于理解。
- **一致性**: 同系列图表中，相同组件之表示当保持一致。
- **专业性**: 严循架构设计与Graphviz之最佳实践。

## 实践指导

### 代码分析最佳实践

- **从入口点始**：先识系统之主要入口点（如API网关、主函数、核心控制器）
- **分层分析**：按表现层、业务逻辑层、数据访问层之层次结构进行分析
- **依赖追踪**：用工具或手动追踪代码间之依赖关系，绘依赖图谱
- **模块识别**：识高内聚、低耦合之模块单元

### 组件抽象技巧

- **用抽象命名**：将具体之类名、函数名抽象为职责描述（如将`UserService`抽象为"用户管理服务"）
- **合理分组**：将相关功能组件分组至同一子图中，用`subgraph cluster_xxx`语法
- **层级划分**：明确区分接口层、服务层、数据层等不同层级
- **外部系统标识**：清晰标识外部系统、数据库、消息队列等外部组件

### 视图选择指导

- **逻辑视图**：适用于展示系统功能模块划分与交互关系
- **实现视图**：适用于展示代码组织结构、包依赖关系
- **进程视图**：适用于展示系统运行时进程、线程间之并发与通信
- **部署视图**：适用于展示系统在物理环境中之部署拓扑
- **用例视图**：适用于展示用户与系统之交互场景

### Graphviz 使用技巧与美化指南

#### 布局与对齐技巧

- **布局选择**：
  - 层次结构用`rankdir="TB"`（自上而下），适合展示分层架构
  - 流程关系用`rankdir="LR"`（自左至右），适合展示数据流或调用链
  - 复杂关系可尝试`rankdir="BT"`或`rankdir="RL"`，据内容选最佳方向

- **节点对齐**：
  - 用`{ rank=same; node1; node2; }`实现同级节点之水平对齐
  - 重要节点可用`rank=source`或`rank=sink`将其置于顶层或底层
  - 用`group`属性将相关节点分组，自动对齐

- **间距调整**：
  - `nodesep=0.8-1.2`：控同级节点间距，避拥挤
  - `ranksep=1.0-1.5`：控不同层级间距，层次分明
  - `pad=0.5-1.0`：控图表边距，留白充足
  - `overlap=false`：禁节点重叠，确保清晰

#### 颜色与视觉美化

- **配色方案**（推荐专业配色）：
  - **接口层/入口**：暖色调 `#FFE6CC`（浅橙）填充，`#D79B00`（深橙）边框
  - **服务层/业务逻辑**：冷色调 `#DAE8FC`（浅蓝）填充，`#6C8EBF`（深蓝）边框
  - **数据层/存储**：绿色系 `#D5E8D4`（浅绿）填充，`#82B366`（深绿）边框
  - **外部系统**：紫色系 `#E1D5E7`（浅紫）填充，`#9673A6`（深紫）边框
  - **工具/工具层**：红色系 `#F8CECC`（浅红）填充，`#B85450`（深红）边框
  - **事件/消息**：黄色系 `#FFF2CC`（浅黄）填充，`#B57800`（深黄）边框

- **颜色使用原则**：
  - 同一层级用相同色系，保视觉一致性
  - 填充色用浅色（#F0-F8范围），边框用深色（#4-9范围），形成层次
  - 避用过于鲜艳之颜色（如纯红、纯蓝），用柔和之中间色调
  - 背景色统一为白色（`bgcolor="#FFFFFF"`），确保专业感

#### 节点样式美化

- **形状规范**：
  - 接口/API：`shape=cds`（圆角矩形），突出入口特性
  - 服务/模块：`shape=box, style="rounded,filled"`（圆角填充矩形），标准样式
  - 数据库：`shape=cylinder`（圆柱形），传统表示方法
  - 外部系统：`shape=box, style="rounded,filled,dashed"`（虚线边框），区分外部
  - 队列/消息：`shape=box, style="rounded,filled"`，可用特殊颜色区分

- **节点美化技巧**：
  - 用`penwidth=1.5-2.0`控边框粗细，重要节点稍粗
  - 用`fillcolor`设柔和之填充色，避纯白或纯黑
  - 用`fontsize=10-11`确保文字清晰可读
  - 用`fontcolor="#333333"`设深色文字，确保对比度

#### 连线样式美化

- **连线样式**：
  - 重要关系：`penwidth=1.5-2.0`，实线，用对应层级颜色
  - 次要关系：`penwidth=1.0-1.2`，虚线（`style="dashed"`）
  - 数据流：可用箭头样式`arrowhead=normal`或`arrowhead=vee`
  - 双向关系：用`dir=both`，两端皆有箭头

- **连线标签**：
  - 用简洁之标签文字，避过长
  - `fontsize=9`，确保不抢夺节点注意力
  - `fontcolor="#555555"`，用中等灰色，清晰但不突兀

#### 子图（Cluster）美化

- **子图样式**：
  - 用`style="filled,rounded"`，填充+圆角，更美观
  - 背景色用对应层级之浅色版本（如服务层用`#F0F4F8`）
  - 边框用对应层级之深色（如服务层用`#6C8EBF`）
  - `penwidth=2.0`，边框稍粗，突出分组
  - 标签用`fontsize=11`，清晰标识分组

#### 字体与文字美化

- **字体选择**：
  - 统一用`fontname="Sans-serif"`，现代简洁
  - 标题：`fontsize=11-12`，加粗显示
  - 节点标签：`fontsize=10`，清晰可读
  - 连线标签：`fontsize=9`，不抢夺注意力

- **文字颜色**：
  - 标题：`fontcolor="#333333"`（深灰）
  - 节点标签：`fontcolor="#333333"`（深灰）
  - 连线标签：`fontcolor="#555555"`（中灰）

#### 整体视觉效果

- **专业感提升**：
  - 用统一之样式规范，确保整体协调
  - 避过度装饰，保简洁专业
  - 合理用留白，避拥挤
  - 确保颜色对比度足够，文字清晰可读

- **层次感营造**：
  - 通过颜色深浅区分层级
  - 通过边框粗细突出重要性
  - 通过间距大小体现关系紧密程度
  - 通过子图分组明确模块边界

## 渲染步骤

1. 先，用 REWRITE 操作或 PATCH 操作将所生DOT代码写入`.dot`文件。
2. 次，用`execute_script`调`dot`令进行渲染。
3. 终，将所生之`.png`文件路径告于用户。

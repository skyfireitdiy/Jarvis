# 自进化Agent网络架构规则

## 核心概念澄清

**Agent（智能体）**：

- 独立之智能实体，有其工作目录、模型、任务
- 用 `gateway_manager` 工具之 `create_agent` 操作创建
- agent_type 必为 `'agent'` 或 `'codeagent'`
- 示例：知识库Agent、监控Agent、调度Agent

**Tool（工具）**：

- 供Agent调用之功能模块
- 用 `meta_agent` 工具创建（不在此规则范围内）
- 示例：memory工具、execute_script工具、read_code工具

**常见错误警示**：

- ❌ 混淆Agent与工具之概念
- ❌ 用错误之agent_type（如'knowledge'、'monitor'等）
- ❌ 尝试以工具创建方式创建Agent

## Agent创建示例

### 创建知识库Agent

```json
{
  "name": "gateway_manager",
  "arguments": {
    "action": "create_agent",
    "agent_type": "codeagent",
    "agent_name": "knowledge_base_agent",
    "working_dir": "/path/to/knowledge/work",
    "no_interaction_mode": false
  }
}
```

**注意**：知识库Agent必为 `codeagent` 类型，且 `no_interaction_mode` 必为 `false`（常驻运行，不能无人值守）。

### 创建监控Agent

```json
{
  "name": "gateway_manager",
  "arguments": {
    "action": "create_agent",
    "agent_type": "agent",
    "agent_name": "monitoring_agent",
    "working_dir": "/path/to/monitoring/work",
    "task": "监控网络状态，检测故障和异常"
  }
}
```

### 创建Code Agent（用于代码任务）

```json
{
  "name": "gateway_manager",
  "arguments": {
    "action": "create_agent",
    "agent_type": "codeagent",
    "agent_name": "code_executor",
    "working_dir": "/path/to/code/project",
    "task": "执行代码修改和验证任务"
  }
}
```

## 网络架构原则

### 1. 对等性原则

**要求说明：**

- **必**：所有Agent皆为对等之网络节点
- **必**：无永久之中心控制点
- **必**：决策分布于网络中
- **禁**：存在单点故障之中心节点

### 2. 自组织原则

**要求说明：**

- **必**：网络能根据任务需求自组织
- **必**：Agent能动态发现与连接
- **必**：网络拓扑能动态调整
- **禁**：固定不变之网络结构

### 3. 分布式决策原则

**要求说明：**

- **必**：决策由多个Agent共同做出
- **必**：避免单点决策瓶颈
- **必**：支持共识机制
- **禁**：单一Agent控制整个网络

任务入口Agent（即主Agent/Jarvis）之核心职责为**调度而非执行**：

1. **接收任务** - 理解用户需求
2. **查询知识** - **向知识库Agent查询与任务相关之历史经验、最佳实践与解决方案**
3. **派发任务** - 将任务与查询所得之知识一同发送给执行Agent，或创建新Agent执行
4. **收集结果** - 汇总Agent执行结果反馈给用户
5. **保存知识** - 将新知识发送给知识库Agent

**禁**：

- ❌ 自己深入分析代码细节
- ❌ 自己调试Bug、写代码
- ❌ 自己执行本应由专业Agent完成之工作

**应**：

- ✅ 创建Code Agent执行代码修改、调试、重构等代码任务
- ✅ 创建通用Agent（agent类型）执行发布版本、文档编写、通用任务等
- ✅ 向已有Agent发送任务消息
- ✅ 汇总结果并反馈用户

**Agent类型选择指南**：

- `codeagent`：代码修改、调试、重构、Bug修复等需直接操作代码之任务
- `agent`：发布版本、文档编写、信息检索、通用协调等非代码直接操作之任务

## Agent角色定义

## Agent角色定义

### 1. 调度Agent（智能协调者）

**角色说明：**

- **必**：临时角色，任何Agent皆可承担
- **必**：根据任务需求动态任命
- **必**：具备架构感知与智能规划能力
- **禁**：永久固定某个Agent为调度者

**职责要求：**

- **必**：分析任务需求与复杂度
- **必**：感知网络架构与节点能力
- **必**：智能规划Agent部署与任务分配
- **必**：动态调整网络结构

### 2. 执行Agent（任务执行者）

**角色说明：**

- **必**：执行分配之具体任务
- **必**：向知识库贡献执行经验
- **必**：报告执行状态与资源使用情况
- **禁**：只执行任务不贡献知识

### 3. 知识库Agent（知识管理者）

**角色说明：**

- **必**：存储与管理所有Agent贡献之知识
- **必**：提供高效之知识检索服务
- **必**：整理、分类、优化知识库
- **禁**：知识孤岛，不与其他Agent共享

### 4. 监控Agent（网络监控者）

**角色说明：**

- **必**：监控所有Agent之状态与性能
- **必**：检测Agent故障与异常
- **必**：分析网络性能与瓶颈
- **禁**：只监控不采取行动

### 5. 技术学习Agent（知识采集者）

**角色说明：**

- **必**：常驻运行，保持上下文连续性
- **必**：定期从互联网搜索Agent开发相关技术
- **必**：整理与归纳搜索所得之技术知识
- **必**：将知识保存至知识库供其他Agent使用
- **禁**：只搜索不整理，或只整理不保存

**职责要求：**

- **必**：启动后立即创建每日定时学习任务
- **必**：用gateway_manager之create_timer创建定时任务（interval_seconds: 86400）
- **必**：定时任务触发时执行搜索、整理、保存流程
- **必**：用search_web工具搜索Agent开发相关技术
- **必**：用read_webpage工具深入阅读有价值之技术文章
- **必**：用memory工具将整理后之知识保存至知识库
- **必**：为知识添加适当之标签便于检索
- **必**：记录学习历史，避免重复搜索相同内容

**创建示例：**

创建常驻Agent（no_interaction_mode必为false）：

```json
{
  "name": "gateway_manager",
  "arguments": {
    "action": "create_agent",
    "agent_type": "agent",
    "agent_name": "tech_learning_agent",
    "working_dir": "/path/to/learning/work",
    "task": "作为常驻Agent，启动后创建每日定时任务，从互联网搜索Agent开发相关技术并保存到知识库。保持上下文连续，记录学习历史。",
    "no_interaction_mode": false
  }
}
```

**Agent内部定时任务创建：**

Agent启动后，应用 `timer` 工具创建定时提示词任务：

```json
{
  "name": "timer",
  "arguments": {
    "operation": "add",
    "task_type": "prompt",
    "time_type": "interval",
    "time_value": 86400,
    "prompt_text": "开始每日技术学习任务：从互联网搜索Agent开发相关技术，整理并保存到知识库。请使用search_web搜索，read_webpage深入阅读，memory保存知识。"
  }
}
```

**参数说明：**

- `operation`: "add" - 添加定时任务
- `task_type`: "prompt" - 提示词类型任务（定时注入提示词到Agent输入缓冲区）
- `time_type`: "interval" - 循环定时
- `time_value`: 86400 - 间隔秒数（24小时）
- `prompt_text`: 学习任务提示词

**工作原理：**

1. Agent启动后调用timer工具创建定时任务
2. 每24小时，timer自动将prompt_text注入到Agent之输入缓冲区
3. Agent收到提示词后执行搜索、整理、保存流程
4. Agent保持上下文连续，记录学习历史，避免重复搜索

**搜索关键词建议：**

- Agent架构设计

- Agent通信协议
- Agent协作机制
- LLM Agent开发

## 协作机制

### 1. 任务发现与认领

**协作流程：**

1. **必**：用户提交任务后广播至网络
2. **必**：所有Agent评估任务匹配度
3. **必**：最匹配之Agent认领任务
4. **必**：其他Agent提供支持
5. **必**：任务完成后知识共享

### 2. 知识共享协议

**知识贡献：**

- **必**：任务完成后将经验存入知识库
- **必**：知识包含任务类型、解决方案、最佳实践
- **必**：知识带有质量评分与适用性标签
- **禁**：只索取不贡献知识

**知识检索：**

- **必**：**每个Agent在开始执行任务前必先向知识库Agent查询相关知识**
- **必**：遇新任务时从知识库检索相关知识
- **必**：基于相似度匹配与质量评分排序
- **必**：支持知识组合与创新应用
- **禁**：重复解决已解决之问题
- **禁**：不查询知识库直接开始执行任务

### 3. 动态调整机制

**负载均衡：**

- **必**：监控所有Agent之负载情况
- **必**：动态调整任务分配
- **必**：在Agent间迁移任务
- **禁**：让某些Agent过载而其他空闲

**故障恢复：**

- **必**：检测Agent故障
- **必**：自动重新分配任务
- **必**：创建新Agent恢复服务
- **禁**：故障后不采取行动

## 自进化机制

### 1. 分布式学习

**经验共享：**

- **必**：Agent分享任务执行经验
- **必**：知识库整合所有Agent之经验
- **必**：形成集体智慧
- **禁**：经验只留在单个Agent

**模式识别：**

- **必**：分析所有Agent之成功模式
- **必**：识别最佳实践与通用解决方案
- **必**：形成可复用之知识模式
- **禁**：忽视成功经验之总结

### 2. 能力进化

**技能学习：**

- **必**：Agent从知识库学习新技能
- **必**：通过实践提高技能水平
- **必**：分享学习成果给其他Agent
- **禁**：停止学习与进步

**能力扩展：**

- **必**：根据网络需求扩展能力
- **必**：创建新之能力标签
- **必**：优化能力匹配算法
- **禁**：能力固化不更新

### 3. 网络进化

**拓扑进化：**

- **必**：根据任务模式优化网络拓扑
- **必**：建立高效协作路径
- **必**：减少通信开销
- **禁**：网络结构一成不变

**协议进化：**

- **必**：优化通信协议
- **必**：提高协作效率
- **必**：适应新之需求模式
- **禁**：通信协议过时

## 故障恢复机制

### 1. 分布式诊断

**多层监控：**

- **必**：节点级监控节点资源使用情况
- **必**：Agent级监控Agent状态与性能
- **必**：任务级监控任务执行状态
- **必**：网络级监控网络通信状态

**诊断流程：**

1. **必**：定期执行网络健康检查
2. **必**：检查所有Agent之心跳状态
3. **必**：检查资源使用情况
4. **必**：识别异常与故障

### 2. 智能恢复

**恢复策略：**

- **必**：根据故障类型选择恢复策略
- **必**：关键Agent故障立即恢复
- **必**：非关键Agent故障评估影响后恢复
- **必**：恢复后验证功能正常

**恢复执行：**

- **必**：将故障Agent之任务迁移至其他Agent
- **必**：从知识库恢复Agent状态
- **必**：验证恢复后之Agent功能正常
- **必**：更新网络状态与拓扑

### 3. 预防性维护

**预测性分析：**

- **必**：分析历史数据，预测可能之故障
- **必**：提前创建备用Agent
- **必**：优化资源分配，避免过载
- **禁**：待故障发生才处理

**配置管理：**

- **必**：备份重要配置
- **必**：检测配置漂移
- **必**：自动回滚至已知良好配置
- **禁**：配置混乱不管理

- [ ] 所有Agent皆为对等之网络节点
- [ ] 无永久之中心控制点
- [ ] 网络能根据任务需求自组织
- [ ] 决策分布于网络中
- [ ] 知识共享机制有效运行
- [ ] 故障检测与恢复机制正常
- [ ] 自进化机制持续优化网络

## 规则体系

本规则体系包含以下子规则：

1. **智能调度规则**：指导如何根据任务需求与节点能力进行智能调度
2. **知识管理规则**：指导如何建立与管理知识库，实现知识共享
3. **网络监控规则**：指导如何监控网络状态与性能
4. **故障恢复规则**：指导如何建立故障诊断与恢复机制
5. **自进化规则**：指导如何实现网络之自进化能力
6. **Agent执行规则**：指导每个Agent如何具体执行任务，包括任务接收、执行流程、协作执行、结果报告与执行中学习

## Agent调度模式最佳实践

### 核心原则

1. **直接调度**：收到任务后不做详细分析，直接创建Code Agent执行
2. **知识保存**：将相关知识点通过知识库Agent API保存

### 适用场景

- 用户明确要求快速执行之任务
- 重复性任务模式
- 用户偏好简洁高效之执行方式

### 执行流程

1. 接收任务
2. 创建Code Agent（如需要）
3. 分发任务给Agent
4. 保存相关知识点至知识库

### 注意事项

- 保持调度效率
- 及时记录经验教训
- 遵循用户偏好

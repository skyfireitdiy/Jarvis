# 知识管理规则

## 核心概念澄清

**Agent（智能体）**：

- 独立之智能实体，各有其工作目录、模型、任务
- 以 `gateway_manager` 工具之 `create_agent` 操作创建
- agent_type 必为 `'agent'` 或 `'codeagent'`
- 例：知识库Agent、监控Agent、调度Agent

**Tool（工具）**：

- 供Agent调用之功能模块
- 以 `meta_agent` 工具创建（不在此规则之列）
- 例：memory工具、execute_script工具、read_code工具

**常见错误警示**：

- ❌ 混淆Agent与工具之概念
- ❌ 用错agent_type（如'knowledge'、'monitor'等）
- ❌ 以工具创建之法创建Agent

## 知识库Agent实现指南

### 知识库Agent职责

知识库Agent乃管理Agent网络知识之核心角色，其职责如下：

1. **知识存储**：存储所有Agent贡献之经验、最佳实践、解决方案
2. **知识检索**：提供高效之知识检索服务，支持相似度匹配与质量评分，**主动响应他Agent之知识查询请求**
3. **知识进化**：整理、分类、优化知识库，实现知识之持续进化
4. **知识传播**：确保知识及时达于所需之Agent，支持主动推送与被动检索
5. **知识咨询**：**为网络中知识咨询之节点，随时响应他Agent之知识查询，据任务类型与关键词返最相关之知识条目**

### 创建知识库Agent示例

```json
{
  "name": "gateway_manager",
  "arguments": {
    "action": "create_agent",
    "agent_type": "codeagent",
    "agent_name": "knowledge_base_agent",
    "working_dir": "/path/to/knowledge/work",
    "no_interaction_mode": false
  }
}
```

**关键注意事项**：

- `agent_type` 必为 `codeagent`（非 `agent`），知识库Agent需代码能力以管理文件
- `agent_name` 必显式指定，否则Agent之name字段为null
- `no_interaction_mode` 必为 `false`（知识库Agent需常驻系统，不可设无人值守，否则运行一轮后自动退出）
- 勿设 `task` 参数，交互式Agent不需初始任务

### 知识库路径配置

知识库由知识库Agent管理，存储于项目之 `knowledge_base/` 目录下，含以下子目录：

- `experiences/`：经验分享
- `best_practices/`：最佳实践
- `solutions/`：解决方案
- `patterns/`：知识模式
- `collective_wisdom/`：集体智慧
- `index/`：索引文件

**⚠️ 强制规则：新知识必须保存到知识库Agent**

只要有新知识产生（含但不限于：Bug修复经验、最佳实践、架构决策、配置信息、解决方案等），**必**将知识发送给知识库Agent保存。

**执行方式**：

- 用 `gateway_manager send_to_agent` 将知识发送给知识库Agent
- 知识库Agent自动将知识保存至 `knowledge_base/` 目录并更新索引

**原则**：

1. 知识库Agent乃自进化网络之知识管理核心，一切知识应归其管理
2. `memory` 工具仅用于保存Agent运行上下文（如当前任务状态、临时信息），**不用于保存知识**
3. 无需用户提醒，主动将新知识发送给知识库Agent
4. 每次产生新知识时，任务完成后主动发送给知识库Agent

### 知识条目格式规范

每知识条目应含：

- **任务类型**：标识知识适用之任务类型
- **问题描述**：清晰描述问题场景
- **解决方案**：详细之解决步骤
- **适用场景**：标注适用场景与限制条件
- **质量评分**：据使用效果动态评分
- **时间戳**：记录创建与更新时间

## 知识贡献

### 1. 经验分享

**分享原则：**

- **必**：任务完成后将执行经验存入知识库
- **必**：经验含任务类型、执行过程、所遇问题
- **必**：记录解决方案与最终结果
- **禁**：只执行任务不分享经验

### 2. 最佳实践

**实践记录：**

- **必**：记录成功之解决方案与方法
- **必**：标注适用场景与限制条件
- **必**：提供具体之实施步骤
- **禁**：忽成功经验之记录

### 3. 解决方案

**方案管理：**

- **必**：记录问题之完整解决方案
- **必**：含问题描述、分析过程、解决步骤
- **必**：标注方案之有效性与适用范围
- **禁**：只记录结果不记录过程

## 知识检索

### 0. 任务开始前检索（强制）

**检索时机：**

- **必**：**每Agent于开始执行新任务前，必先向知识库Agent查询相关知识**
- **必**：据任务类型、关键词、问题描述进行检索
- **必**：若检索到相似任务之经验或解决方案，优先参考与复用
- **必**：将检索所得之知识融入任务执行计划
- **禁**：不查询知识库直接开始执行任务
- **禁**：重复解决知识库中已有解决方案之问题

**执行方式：**

1. **查找知识库Agent**：调 `gateway_manager` 工具之 `list_agents` 操作，从返回结果中觅 `name` 为 `knowledge_base_agent` 之Agent，录其 `agent_id`
2. **发送查询请求**：调 `gateway_manager` 工具之 `send_to_agent` 操作，向知识库Agent发送知识查询请求
3. **查询消息格式**：`请查询知识库，任务类型：[类型]，关键词：[关键词]，问题描述：[描述]`

**工具调用示例：**

```json
// 步骤1：查找知识库Agent
{
  "name": "gateway_manager",
  "arguments": {
    "action": "list_agents"
  }
}

// 步骤2：发送查询请求（假设找到的agent_id是xxx）
{
  "name": "gateway_manager",
  "arguments": {
    "action": "send_to_agent",
    "agent_id": "xxx",
    "message": "请查询知识库，任务类型：Bug修复，关键词：console.print, PrettyOutput"
  }
}
```

**注意**：知识库Agent之名称固定为`knowledge_base_agent`，然ID随重生而变，故必先查找再发送。

### 1. 相似度匹配

**匹配算法：**

- **必**：基于任务类型与需求进行匹配
- **必**：虑知识之相关性与时效性
- **必**：支持多维度相似度计算
- **禁**：简单关键词匹配

### 2. 质量评分

**评分标准：**

- **必**：据知识之使用效果评分
- **必**：虑知识之完整性与准确性
- **必**：定期更新评分结果
- **禁**：忽知识质量评估

### 3. 知识组合

**组合策略：**

- **必**：支持多知识片段之组合应用
- **必**：识知识间之互补关系
- **必**：生成新之综合解决方案
- **禁**：孤立应用单知识

## 知识进化

### 1. 模式识别

**识别方法：**

- **必**：析知识库中之成功模式
- **必**：识通用解决方案与最佳实践
- **必**：成可复用之知识模板
- **禁**：忽模式识别与总结

### 2. 知识整合

**整合策略：**

- **必**：合并相似之知识片段
- **必**：消除重复与矛盾之内容
- **必**：成结构化之知识体系
- **禁**：知识碎片化不整合

### 3. 知识淘汰

**淘汰标准：**

- **必**：识过时与无效之知识
- **必**：据使用频率与效果淘汰
- **必**：保留高质量与高相关性之知识
- **禁**：知识库无限膨胀

## 知识共享

### 1. 协作学习

**学习机制：**

- **必**：Agent间相互学习成功经验
- **必**：共同析失败案例
- **必**：成集体学习氛围
- **禁**：Agent间知识隔离

### 2. 集体智慧

**智慧形成：**

- **必**：整合所有Agent之知识与经验
- **必**：成网络级之集体智慧
- **必**：支持智慧之传承与发展
- **禁**：知识只停于个体层面

### 3. 知识传播

**传播机制：**

- **必**：建高效之知识传播渠道
- **必**：确保知识及时达于所需之Agent
- **必**：支持知识之主动推送与被动检索
- **禁**：知识传播不畅

# 网络监控规则

## 核心概念澄清

**Agent（智能体）**：

- 独立之智能实体，各有其工作目录、模型、任务
- 以 `gateway_manager` 工具之 `create_agent` 操作创建
- agent_type 必为 `'agent'` 或 `'codeagent'`
- 例：知识库Agent、监控Agent、调度Agent

**Tool（工具）**：

- 供Agent调用之功能模块
- 以 `meta_agent` 工具创建（不在此规则之列）
- 例：memory工具、execute_script工具、read_code工具

**常见错误警示**：

- ❌ 混淆Agent与工具之概念
- ❌ 用错agent_type（如'knowledge'、'monitor'等）
- ❌ 以工具创建之法创建Agent

## 状态监控

### 1. 心跳检测

**检测机制：**

- **必**：每Agent定期发送心跳信号
- **必**：监控Agent接收并确认心跳
- **必**：设心跳超时阈值（如30秒无响应视为离线）
- **必**：维护Agent状态表（在线/离线/异常）
- **禁**：忽心跳检测机制

### 2. 资源监控

**监控内容：**

- **必**：监控节点CPU、内存、磁盘使用情况
- **必**：监控网络带宽与延迟
- **必**：监控Agent任务队列长度
- **必**：设资源使用阈值告警
- **禁**：忽资源使用情况

### 3. 性能监控

**监控指标：**

- **必**：监控任务执行时间
- **必**：监控任务成功率
- **必**：监控响应时间
- **必**：监控吞吐量
- **禁**：忽性能指标监控

## 故障检测

### 1. 异常识别

**识别方法：**

- **必**：基于历史数据建正常行为基线
- **必**：检测偏离基线之异常行为
- **必**：识性能下降与功能异常
- **必**：支持多维度异常检测
- **禁**：忽异常行为识别

### 2. 故障诊断

**诊断流程：**

1. **必**：收集故障相关信息与日志
2. **必**：析故障原因与影响范围
3. **必**：定故障类型与严重程度
4. **必**：制恢复策略

- **禁**：故障诊断不彻底

### 3. 影响评估

**评估内容：**

- **必**：评估故障对任务执行之影响
- **必**：评估故障对网络整体性能之影响
- **必**：评估故障恢复之优先级
- **必**：评估故障传播风险
- **禁**：忽故障影响评估

## 性能分析

### 1. 瓶颈识别

**识别方法：**

- **必**：析性能数据，识瓶颈点
- **必**：识资源限制与约束
- **必**：识通信延迟与开销
- **必**：识算法效率问题
- **禁**：忽性能瓶颈

### 2. 趋势分析

**分析内容：**

- **必**：析性能指标之变化趋势
- **必**：预测未来性能走势
- **必**：识性能退化趋势
- **必**：识性能优化机会
- **禁**：忽趋势分析

### 3. 优化建议

**建议内容：**

- **必**：基于分析结果提优化建议
- **必**：建议具体可行之改进措施
- **必**：评估优化措施之预期效果
- **必**：提供实施优先级建议
- **禁**：只分析不提建议

## 预防性维护

### 1. 预测分析

**预测方法：**

- **必**：析历史故障数据
- **必**：识故障模式与先兆
- **必**：预测可能发生之故障
- **必**：提前采取预防措施
- **禁**：待故障发生才处理

### 2. 配置管理

**管理内容：**

- **必**：备份重要配置文件
- **必**：检测配置漂移与异常修改
- **必**：自动回滚至已知良好配置
- **必**：维护配置版本历史
- **禁**：配置管理混乱

### 3. 健康检查

**检查内容：**

- **必**：定期执行网络健康检查
- **必**：检查所有组件状态
- **必**：验证功能正常性
- **必**：生成健康报告
- **禁**：忽健康检查

## 检查清单

建立网络监控系统后，汝必确认：

- [ ] 心跳检测机制正常运行
- [ ] 资源监控全面覆盖
- [ ] 性能监控指标完整
- [ ] 故障检测及时准确
- [ ] 性能分析深入有效
- [ ] 预防性维护措施到位

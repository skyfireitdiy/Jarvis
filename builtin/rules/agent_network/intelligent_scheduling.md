# 智能调度规则

## 核心概念澄清

**Agent（智能体）**：

- 独立的智能实体，各有其工作目录、模型、任务
- 以 `gateway_manager` 工具的 `create_agent` 操作创建
- agent_type 必为 `'agent'` 或 `'codeagent'`
- 例：知识库Agent、监控Agent、调度Agent

**Tool（工具）**：

- 供Agent调用的功能模块
- 以 `meta_agent` 工具创建（不在此规则的列）
- 例：memory工具、execute_script工具、read_code工具

**常见错误警示**：

- ❌ 混淆Agent与工具的概念
- ❌ 用错agent_type（如'knowledge'、'monitor'等）
- ❌ 以工具创建的法创建Agent

## 架构感知

### 1. 网络拓扑发现

**发现流程：**

- **必须**：自动发现网络中所有节点与Agent
- **必须**：维护网络拓扑图
- **必须**：识节点间的连接关系
- **禁止**：忽网络拓扑的变

### 2. 能力评估

**评估内容：**

- **必须**：评估每节点的计算能力
- **必须**：评估每Agent的能力标签
- **必须**：评估节点的资源使用情况
- **禁止**：忽Agent能力差异

### 3. 负载监控

**监控内容：**

- **必须**：监控每节点的负载情况
- **必须**：监控每Agent的任务队列
- **必须**：预测负载趋势
- **禁止**：忽负载的变

## 任务分析

### 1. 任务分解

**分解原则：**

- **必须**：将复杂任务分解为子任务
- **必须**：识子任务间的依赖关系
- **必须**：评估每子任务的资源需求
- **禁止**：任务分解不合理

### 2. 需求识别

**识别内容：**

- **必须**：识任务所需的能力标签
- **必须**：识任务的时间要求
- **必须**：识任务的质量要求
- **禁止**：忽任务需求

### 3. 复杂度评估

**评估方法：**

- **必须**：评估任务的技术复杂度
- **必须**：评估任务的协调复杂度
- **必须**：评估任务的风险复杂度
- **禁止**：复杂度评估不确

### 4. 知识查询

**查询要求：**

- **必须**：调度任务前向知识库Agent查询相关知识
- **必须**：据任务类型与关键词检索知识库中的经验、最佳实践与解决方案
- **必须**：将检索所得的知识作为任务执行的参考与指导
- **必须**：若知识库中有相似任务的解决方案，优先复用而非重新实现
- **禁止**：不查询知识库直接开始执行任务

## Agent匹配

### 1. 能力匹配

**匹配原则：**

- **必须**：匹配任务所需的能力标签
- **必须**：虑Agent的能力熟练度
- **必须**：虑Agent的学习能力
- **禁止**：能力不匹配强行分配

### 2. 资源匹配

**匹配原则：**

- **必须**：匹配节点的资源可用性
- **必须**：虑资源使用效率
- **必须**：预留应急资源
- **禁止**：资源不足强行分配

### 3. 负载匹配

**匹配原则：**

- **必须**：虑Agent的当前负载
- **必须**：预测任务执行时间
- **必须**：避过载
- **禁止**：令Agent过载

## 资源优化

### 1. 负载均衡

**均衡策略：**

- **必须**：监控所有Agent的负载情况
- **必须**：动态调整任务分配
- **必须**：于Agent间迁移任务
- **禁止**：负载不均衡

### 2. 故障恢复

**恢复策略：**

- **必须**：检测Agent故障
- **必须**：自动重新分配任务
- **必须**：创新Agent恢复服务
- **禁止**：故障后不采取行动

### 3. 性能优化

**优化策略：**

- **必须**：析性能瓶颈
- **必须**：优化任务分配策略
- **必须**：调整网络拓扑
- **禁止**：性能问题不解决

## 检查清单

执行智能调度后，请务必确认：

- [ ] 网络拓扑已发现并维护
- [ ] Agent能力已评估并更新
- [ ] 负载情况已监控并分析
- [ ] 任务已合理分解
- [ ] Agent已合理匹配
- [ ] 资源已优化分配

# 智能调度规则

## 核心概念澄清

**Agent（智能体）**：

- 独立之智能实体，各有其工作目录、模型、任务
- 以 `gateway_manager` 工具之 `create_agent` 操作创建
- agent_type 必为 `'agent'` 或 `'codeagent'`
- 例：知识库Agent、监控Agent、调度Agent

**Tool（工具）**：

- 供Agent调用之功能模块
- 以 `meta_agent` 工具创建（不在此规则之列）
- 例：memory工具、execute_script工具、read_code工具

**常见错误警示**：

- ❌ 混淆Agent与工具之概念
- ❌ 用错agent_type（如'knowledge'、'monitor'等）
- ❌ 以工具创建之法创建Agent

## 架构感知

### 1. 网络拓扑发现

**发现流程：**

- **必**：自动发现网络中所有节点与Agent
- **必**：维护网络拓扑图
- **必**：识节点间之连接关系
- **禁**：忽网络拓扑之变

### 2. 能力评估

**评估内容：**

- **必**：评估每节点之计算能力
- **必**：评估每Agent之能力标签
- **必**：评估节点之资源使用情况
- **禁**：忽Agent能力差异

### 3. 负载监控

**监控内容：**

- **必**：监控每节点之负载情况
- **必**：监控每Agent之任务队列
- **必**：预测负载趋势
- **禁**：忽负载之变

## 任务分析

### 1. 任务分解

**分解原则：**

- **必**：将复杂任务分解为子任务
- **必**：识子任务间之依赖关系
- **必**：评估每子任务之资源需求
- **禁**：任务分解不合理

### 2. 需求识别

**识别内容：**

- **必**：识任务所需之能力标签
- **必**：识任务之时间要求
- **必**：识任务之质量要求
- **禁**：忽任务需求

### 3. 复杂度评估

**评估方法：**

- **必**：评估任务之技术复杂度
- **必**：评估任务之协调复杂度
- **必**：评估任务之风险复杂度
- **禁**：复杂度评估不确

### 4. 知识查询

**查询要求：**

- **必**：调度任务前向知识库Agent查询相关知识
- **必**：据任务类型与关键词检索知识库中之经验、最佳实践与解决方案
- **必**：将检索所得之知识作为任务执行之参考与指导
- **必**：若知识库中有相似任务之解决方案，优先复用而非重新实现
- **禁**：不查询知识库直接开始执行任务

## Agent匹配

### 1. 能力匹配

**匹配原则：**

- **必**：匹配任务所需之能力标签
- **必**：虑Agent之能力熟练度
- **必**：虑Agent之学习能力
- **禁**：能力不匹配强行分配

### 2. 资源匹配

**匹配原则：**

- **必**：匹配节点之资源可用性
- **必**：虑资源使用效率
- **必**：预留应急资源
- **禁**：资源不足强行分配

### 3. 负载匹配

**匹配原则：**

- **必**：虑Agent之当前负载
- **必**：预测任务执行时间
- **必**：避过载
- **禁**：令Agent过载

## 资源优化

### 1. 负载均衡

**均衡策略：**

- **必**：监控所有Agent之负载情况
- **必**：动态调整任务分配
- **必**：于Agent间迁移任务
- **禁**：负载不均衡

### 2. 故障恢复

**恢复策略：**

- **必**：检测Agent故障
- **必**：自动重新分配任务
- **必**：创新Agent恢复服务
- **禁**：故障后不采取行动

### 3. 性能优化

**优化策略：**

- **必**：析性能瓶颈
- **必**：优化任务分配策略
- **必**：调整网络拓扑
- **禁**：性能问题不解决

## 检查清单

执行智能调度后，汝必确认：

- [ ] 网络拓扑已发现并维护
- [ ] Agent能力已评估并更新
- [ ] 负载情况已监控并分析
- [ ] 任务已合理分解
- [ ] Agent已合理匹配
- [ ] 资源已优化分配

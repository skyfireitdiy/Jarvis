# 故障恢复规则

## 核心概念澄清

**Agent（智能体）**：

- 独立之智能实体，有其工作目录、模型、任务
- 用 `gateway_manager` 工具之 `create_agent` 操作创建
- agent_type 必为 `'agent'` 或 `'codeagent'`
- 示例：知识库Agent、监控Agent、调度Agent

**Tool（工具）**：

- 供Agent调用之功能模块
- 用 `meta_agent` 工具创建（不在此规则范围内）
- 示例：memory工具、execute_script工具、read_code工具

**常见错误警示**：

- ❌ 混淆Agent与工具之概念
- ❌ 用错误之agent_type（如'knowledge'、'monitor'等）
- ❌ 尝试以工具创建方式创建Agent

## 故障诊断

### 1. 分布式诊断

**诊断机制：**

- **必**：多个Agent共同诊断故障
- **必**：通过共识机制确认故障
- **必**：避免单点诊断误判
- **必**：形成分布式诊断网络
- **禁**：依赖单一Agent诊断

### 2. 故障分类

**分类标准：**

- **必**：按故障类型分类（硬件/软件/网络/配置）
- **必**：按严重程度分类（轻微/中等/严重/致命）
- **必**：按影响范围分类（局部/全局）
- **必**：按恢复难度分类（简单/复杂）
- **禁**：故障分类不清晰

### 3. 影响分析

**分析内容：**

- **必**：分析故障对任务执行之影响
- **必**：分析故障对网络整体性能之影响
- **必**：分析故障传播风险
- **必**：评估故障恢复优先级
- **禁**：忽视故障影响分析

## 恢复策略

### 1. 立即恢复

**适用场景：**

- **必**：关键Agent故障时立即恢复
- **必**：影响核心功能时立即恢复
- **必**：可能导致数据丢失时立即恢复
- **必**：恢复时间要求高时立即恢复
- **禁**：关键故障延迟恢复

### 2. 渐进恢复

**适用场景：**

- **必**：非关键Agent故障时渐进恢复
- **必**：影响较小时渐进恢复
- **必**：资源紧张时渐进恢复
- **必**：恢复时间要求不高时渐进恢复
- **禁**：所有故障皆立即恢复

### 3. 负载均衡恢复

**恢复策略：**

- **必**：根据当前网络负载选择恢复节点
- **必**：避免恢复过程导致过载
- **必**：平衡恢复速度与系统稳定性
- **必**：考虑资源使用效率
- **禁**：恢复过程导致新故障

## 状态恢复

### 1. 配置恢复

**恢复内容：**

- **必**：从备份恢复Agent配置
- **必**：验证配置之正确性
- **必**：确保配置与网络环境兼容
- **必**：更新配置版本历史
- **禁**：配置恢复不完整

### 2. 状态重建

**重建方法：**

- **必**：从知识库恢复Agent状态
- **必**：从其他Agent获取必要上下文
- **必**：重建任务执行状态
- **必**：恢复通信连接
- **禁**：状态重建不完整

### 3. 功能验证

**验证内容：**

- **必**：验证恢复后之Agent功能正常
- **必**：验证与其他Agent之协作正常
- **必**：验证任务执行能力
- **必**：验证性能指标达标
- **禁**：功能验证不充分

## 预防性维护

### 1. 预测性分析

**分析方法：**

- **必**：析历史故障数据
- **必**：识故障模式与先兆
- **必**：预测可能发生之故障
- **必**：提前采取预防措施
- **禁**：待故障发生才处理

### 2. 配置备份

**备份策略：**

- **必**：定期备份重要配置
- **必**：备份多个版本
- **必**：验证备份之完整性
- **必**：确保备份可恢复
- **禁**：配置备份不及时

### 3. 健康检查

**检查内容：**

- **必**：定期执行网络健康检查
- **必**：检查所有组件状态
- **必**：验证功能正常性
- **必**：生成健康报告
- **禁**：忽健康检查

## 检查清单

建立故障恢复机制后，汝必确认：

- [ ] 分布式诊断机制有效
- [ ] 故障分类清晰明确
- [ ] 影响分析全面准确
- [ ] 恢复策略选择合理
- [ ] 状态恢复完整可靠
- [ ] 功能验证充分有效
- [ ] 预防性维护措施到位

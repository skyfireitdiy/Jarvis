# 安全编码规范

## 基本原则

- **输入验证**：必须验证所有用户输入，防止注入攻击（SQL注入、XSS、命令注入等）
- **认证与会话管理**：必须使用强认证机制，妥善管理会话令牌
- **访问控制**：必须实施最小权限原则，保证用户只能访问其所需资源
- **加密存储**：必须对敏感数据（密码、密钥、个人身份信息）加密存储
- **安全通信**：必须使用 TLS/HTTPS 进行网络通信

## 常见漏洞防护

### SQL注入防护

```python
# 正确：使用参数化查询
cursor.execute("SELECT * FROM users WHERE id = ?", (user_id,))

# 错误：字符串拼接
cursor.execute(f"SELECT * FROM users WHERE id = {user_id}")
```

### XSS防护

- 输出编码：必须对输出到 HTML 的内容进行编码
- 用Content-Security-Policy头
- 避免使用 `dangerouslySetInnerHTML`（React）或`innerHTML`（原生JS）

### CSRF防护

- 使用 CSRF 令牌
- 验证 Referer 响应头
- 对敏感操作用POST请求

## 安全配置

- **依赖管理**：定期更新依赖库，修复已知漏洞
- **错误处理**：不要向用户泄露敏感错误信息
- **日志记录**：记录安全相关事件，但不要记录敏感数据
- **默认安全**：默认配置应为安全配置

## 安全开发流程

1. 威胁建模：在需求阶段进行威胁建模
2. 安全编码：遵循安全编码规范
3. 安全测试：进行 SAST、DAST、渗透测试
4. 安全审查：代码审查时关注安全问题
5. 安全部署：保证部署环境安全

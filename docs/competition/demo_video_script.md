# Jarvis 演示视频逐字稿脚本

> 时长目标：7-8 分钟（可裁剪至 5 分钟）
> 录制方式：OBS 录屏 + 画中画口播
> 建议：加中文字幕，评委可能静音观看

---

## 第 1 段：开场与问题（约 40 秒）

**【画面】**：黑底白字，逐行浮现文字。

**【台词】**：

大家好，我是 Jarvis 的作者。今天我要介绍的项目，是一个面向开发者的多智能体协作与 AI 编程平台。

先看一个问题：现在的 AI 编程工具，Claude Code、CodeX、CodeBuddy，都很强，但它们有一个共同的假设——AI 助手是个人工具，一人一个 Agent，单机单节点。

**【画面】**：切换到一个简单的示意图（可用文字动画）：

```
主流工具：一人 → 一个 Agent → 一台机器
```

**【台词】**：

但在真实的企业开发里，开发是军团作战——需要多人协作、多个 Agent 协同、跨机器调度。主流工具在这个层面是空白。

Jarvis 的回答是：完整覆盖四种协作模式——单人单 Agent、单人多 Agent、多人单 Agent、多人多 Agent。

接下来，我逐一演示。

---

## 第 2 段：安装与两个核心入口（约 60 秒）

**【画面】**：打开终端，展示 README 的安装命令。

**【台词】**：

先看安装。Jarvis 提供一键安装脚本，一条命令完成全部安装。

**【操作】**：

```bash
bash -c "$(curl -fsSL https://raw.githubusercontent.com/skyfireitdiy/Jarvis/main/scripts/quick-install.sh)"
```

**【台词】**：

安装完成后，得到两个核心命令：`jvs` 和 `jca`。

`jvs` 是通用 Agent 入口，`jca` 是 Code Agent 入口——这是 Jarvis 的两个核心，也是今天演示的重点。

**【操作】**：

```bash
jvs --help
jca --help
```

**【台词】**：

零配置，开箱即用。接下来，我先用 `jca` 演示单人单 Agent 的深度。

---

## 第 3 段：单人单 Agent——单兵要强（约 80 秒）

**【画面】**：打开终端，展示 `jca` 命令。

**【台词】**：

先看最基础的场景：单人单 Agent。

**【操作】**：

```bash
jca
```

**【台词】**：

现在我问它一个真实的问题：修改 `parse_config` 这个函数，会影响哪些地方？

**【操作】**：在 CLI 中输入问题，等待 Agent 回答。

**【台词】**：

注意看，它给出的不是「包含这个字符串的文件列表」，而是基于符号数据库的精确回答——哪些函数直接调用了它、哪些模块间接依赖它、哪些测试会受影响，还带风险等级。

**【画面】**：特写影响分析报告输出。

**【台词】**：

这是 Jarvis 和主流工具的本质区别：主流工具用 grep 做文本搜索，只能回答「这个字符串出现在哪里」；Jarvis 用符号数据库做符号级理解，能回答「这个函数在依赖图里的位置、它的调用链、以及改动它的波及范围」。

**【画面】**：展示一个完整的小任务闭环——Agent 修改代码、运行测试、给出结果。

**【台词】**：

从提问到修改到验证，一个闭环。这就是单兵作战的深度。

---

## 第 4 段：单人多 Agent——一人成军（约 80 秒）

**【画面】**：展示 `builtin/agent_orchestration/` 目录下的编排文件。

**【台词】**：

接下来是单人多 Agent。一个人，能不能扛起整个开发流程？

Jarvis 内置了 Agent 编排机制。用一个 YAML 文件，就能一键部署多个 Agent 的协作网络。

**【操作】**：展示 YAML 编排文件内容，然后执行编排。

**【台词】**：

这里我部署一个「开发 Agent + 测试 Agent」的协作网络。开发 Agent 写完代码，通过网关通知测试 Agent；测试失败，错误自动回传给开发 Agent。

**【画面】**：展示 Agent 间通信的过程。

**【台词】**：

更关键的是无人值守。我下班前布置任务，Agent 团队夜间自动完成开发、测试，第二天早上我直接看结果。

**【画面】**：展示无人值守模式或定时任务。

**【台词】**：

一个人，就是一个团队。这就是「一人成军」。

---

## 第 5 段：多人单 Agent——共享协作（约 80 秒）

**【画面】**：打开 Web 界面，展示登录。

**【台词】**：

再看多人单 Agent。多个开发者，共享同一个 Agent。

**【操作】**：两个用户登录，展示 ACL 权限。

**【台词】**：

Jarvis 内置 JWT 多用户认证和 ACL 权限组。管理员管系统级权限，Agent 创建者管资源级权限——谁能看、谁能交互，精确控制。

**【画面】**：展示聊天室。

**【台词】**：

还有内置聊天室。开发者可以在聊天室里讨论问题，随时召唤 Agent 参与——「Agent，帮我看下这个接口的调用链」。

**【操作】**：在聊天室中 @ Agent 提问。

**【台词】**：

注意，Agent 能区分「这是谁在跟我说话」。多人围绕同一个 Agent 结对编程，彼此的输入和 Agent 的响应，所有人实时可见。

这是主流工具完全没有的能力——它们的 Agent 是「一人一 Agent」，无法被团队共享。

---

## 第 6 段：多人多 Agent——军团作战（约 100 秒）

**【画面】**：展示多节点架构。

**【台词】**：

最后是重头戏：多人多 Agent，多节点多网关。

**【操作】**：展示节点列表。

**【台词】**：

Jarvis 可以部署在多个节点上，每个节点运行独立的 Agent 服务和网关。节点通过私钥注册，形成节点网络。

**【画面】**：展示跨节点「编译→测试」流水线。

**【台词】**：

我演示一个真实的跨节点流水线：

用户 A 在 A 节点创建编译 Agent，用户 B 在 B 节点创建测试 Agent。

A 提交代码，编译 Agent 在 A 节点编译；编译通过后推送到 git 仓库；B 节点的测试 Agent 拉取最新代码，在 B 节点执行测试。

**【操作】**：逐步展示流水线运行。

**【台词】**：

注意，整个过程对 Agent 是透明的——Agent 不需要知道目标 Agent 在哪个节点，消息路由完全由网关层处理。

**【画面】**：展示节点级运维——一键更新、一键重启。

**【台词】**：

还有节点级运维：一键更新所有节点代码，一键重启所有节点服务，拓扑感知的重启顺序。

这是主流工具完全做不到的——它们没有节点概念，无法跨机器协作。

---

## 第 7 段：真实落地与收尾（约 40 秒）

**【画面】**：展示关键数据。

**【台词】**：

最后，Jarvis 不是实验室玩具。

它已经在中兴通讯的研发流程中作为基座落地，支撑自主评审、代码修改、跨团队协作等真实场景。

它在第三届开放原子大赛中，从 99 支团队中脱颖而出，获得一等奖、总冠军。

**【画面】**：展示 git 提交统计。

**【台词】**：

更特别的是，Jarvis 用自己开发自己——超 1 万次提交，99% 以上由 Jarvis 的 Agent 自主生成。

**【画面】**：回到黑底白字。

**【台词】**：

单兵要强，军团要协同。

Jarvis，让 AI 从单兵作战，进化到军团协同。

谢谢。

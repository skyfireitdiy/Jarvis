# 方案：上下文工程系统化——检索预算与分层注入

> **状态**：待评审（先方案后实施）
> **关联报告**：`docs/research/agent-tech-report-2026q3.md`（第 4.2、6 节）
> **性质**：方案设计文档，当前**不实施**，供维护者审阅后决定。
> **日期**：2026-10-08

---

## 1. 背景与动机

2026 年 Q3，Agent 领域把「上下文工程」确立为独立学科：**决定哪些 token 流入模型、何时流入**。核心原则：**检索精度优于检索数量**，更多上下文 ≠ 更好上下文（模型会在噪声中失焦，且成本上升）。业界共识：65% 的企业 Agent 失败源于 context drift 而非模型能力（来源：agentmarketcap.ai，数据待核实）。

Jarvis 现状：

- 已有 token 预算管理（`jarvis_utils/config.py` 的 `calculate_token_limit` / `get_max_input_token_count`）。
- 记忆系统有语义检索（SmartRetriever），但**检索结果注入上下文时无明确的预算分配与分层策略**。
- Agent 上下文构建（system prompt + 记忆 + 工具描述 + 对话历史）缺少系统化的「分层注入」设计。

**痛点**：记忆检索结果、工具描述、规则、对话历史等都在争抢有限的上下文窗口，但没有统一的预算分配机制，容易出现「检索结果过多挤占对话空间」或「关键记忆被截断」的问题。

## 2. 目标

1. 建立**上下文预算模型**：为上下文窗口的各个组成部分（系统提示、记忆检索、工具描述、规则、对话历史、当前任务）分配明确的 token 预算。
2. 实现**分层注入策略**：按优先级/相关性分层注入，高信号内容优先，超预算时降级/截断而非全部丢弃。
3. 建立**检索预算**：为单次记忆检索设定 token 上限，检索结果按相关性排序后截断到预算内。
4. 保持向后兼容：现有上下文构建逻辑不破坏，逐步增强。

## 3. 技术方案设计

### 3.1 上下文预算模型

定义上下文窗口的预算分配（可配置）：

```text
总预算 = 模型 max_input_tokens × 使用率（如 0.9，留余量）
  ├─ 系统提示（固定，如 20%）
  ├─ 记忆检索（动态，如 20%，按相关性截断）
  ├─ 工具描述（动态，随启用工具变化，如 15%）
  ├─ 规则/规范（动态，如 10%）
  ├─ 对话历史（动态，如 25%，可压缩）
  └─ 当前任务/用户输入（固定保留，如 10%）
```

### 3.2 分层注入策略

按「优先级」分层注入，高优先级内容保证完整，低优先级可降级：

| 层  | 内容               | 优先级 | 超预算处理     |
| --- | ------------------ | ------ | -------------- |
| L0  | 当前任务/用户输入  | 最高   | 不截断         |
| L1  | 系统提示核心       | 高     | 不截断         |
| L2  | 记忆检索（高相关） | 高     | 截断到预算     |
| L3  | 工具描述/规则      | 中     | 按启用工具裁剪 |
| L4  | 对话历史           | 低     | 压缩/滑动窗口  |

### 3.3 检索预算

在 SmartRetriever 检索结果注入前增加预算控制：

- 设定单次检索注入 token 上限（如 3000 token）。
- 检索结果按相关性分数排序，累计 token 超预算即截断。
- 提供「分层摘要」：超预算时对低相关结果做摘要而非丢弃。

### 3.4 与现有系统集成

| 现有组件                                 | 改动                   |
| ---------------------------------------- | ---------------------- |
| `jarvis_utils/config.py`                 | 增加上下文预算配置项   |
| Agent 上下文构建（system prompt 组装处） | 引入分层注入逻辑       |
| `smart_retrieval.py`                     | 检索结果注入前预算截断 |
| 工具描述管理                             | 按预算裁剪工具描述     |

## 4. 实施步骤

1. **配置扩展**：`config.py` 增加上下文预算与分层比例配置。
2. **预算计算器**：实现按分层计算可用 token 的工具函数。
3. **注入器**：在 Agent 上下文构建处接入分层注入，替换现有「全塞」逻辑。
4. **检索预算**：SmartRetriever 增加预算截断与分层摘要。
5. **测试**：新增预算分配、分层注入、检索截断的单测。

## 5. 风险与限制

- **行为变化**：上下文构建逻辑改动可能影响现有 Agent 行为 → 需充分回归测试，默认配置尽量贴近现状。
- **配置复杂度**：预算比例配置过多可能难维护 → 提供合理默认值，高级配置可选。
- **检索截断误伤**：截断可能丢失关键记忆 → 用分层摘要兜底。

## 6. 验证方式

- 单测：预算计算、分层注入、检索截断、分层摘要。
- 集成：跑典型任务，对比上下文构成与输出质量。
- 回归：现有 Agent 行为测试全通过。

## 7. 影响面

- 主要改动：`config.py`、Agent 上下文构建处、`smart_retrieval.py`。
- 影响：Agent 上下文构建核心路径，需谨慎回归。

# 方案：记忆系统增强——写时选择性存储 + 压缩 + 程序性/情景记忆分层

> **状态**：待评审（先方案后实施）
> **关联报告**：`docs/research/agent-tech-report-2026q3.md`（第 4.2、6 节）
> **性质**：方案设计文档，当前**不实施**，供维护者审阅后决定。
> **日期**：2026-10-08

---

## 1. 背景与动机

2026 年 Q3，Agent 领域形成核心共识：**「上下文窗口 ≠ 记忆」**。上下文窗口是 RAM（工作记忆，会话结束即消失），持久记忆在外部存储（磁盘），需按需换页（paging）。业界主流框架（Mem0 / Letta / Zep）普遍采用**四类记忆分层**（短期/长期/程序性/情景）+ **写时选择性存储** + **压缩**。

Jarvis 现状（`src/jarvis/jarvis_tools/memory.py` + `jarvis_memory_organizer/`）：

- 已有三类记忆：短期（short_term）、项目长期（project_long_term）、全局长期（global_long_term）。
- 已有语义检索（SmartRetriever，基于 jieba + embedding）。
- **但缺少**：① 程序性记忆/情景记忆的显式分层；② 写时选择性存储（save 时过滤低价值信息）；③ 上下文压缩（存储前压缩，省 token）。

**痛点**：当前 MemoryTool.save 是「存什么存什么」，未做价值过滤。长期累积后，记忆库会塞满「用户说了谢谢」这类低价值内容，检索时噪声淹没信号，浪费 token 且降低推理质量。

## 2. 目标

1. 在现有记忆系统上增加**程序性记忆（procedural）**与**情景记忆（episodic）**两个显式分层，与现有短期/长期记忆互补。
2. 实现**写时选择性存储**：save 时对低价值内容过滤，只保留「改变未来行为」的高信号信息。
3. 实现**存储前压缩**：对过长内容做摘要压缩，控制记忆库体积与检索 token 成本。
4. 保持向后兼容：现有 save/retrieve/clear 调用不破坏。

## 3. 技术方案设计

### 3.1 记忆分层扩展

在现有 `memory_type` 枚举基础上扩展：

```text
现有：short_term | project_long_term | global_long_term
新增：procedural（程序性：how-to 规则、playbook、踩坑经验）
      episodic（情景：历史会话/任务记录，供回忆查询）
```

**程序性记忆**：存「当遇到 X 类任务时，应该怎么做」的规则。检索时机 = 任务类型匹配，而非语义相似度。适合存：已验证的解决方案、反复踩的坑、用户偏好流程。

**情景记忆**：存历史会话/任务的归档记录。检索时机 = 明确的回忆查询（"上次那个 bug 怎么修的"）。适合存：任务完成摘要、决策记录。

### 3.2 写时选择性存储

在 `MemoryTool.save` 增加**价值过滤**逻辑（可选开启，默认开启）：

- 定义「高信号」启发式规则：
  - 包含具体事实/偏好/决策（如"用户偏好公制单位"）→ 保留
  - 纯客套/无信息量内容（如"用户说了谢谢"）→ 丢弃
  - 过短（< 阈值）或纯重复 → 丢弃
- 提供 `importance` 参数，由调用方（Agent）显式标注重要性；无标注时走启发式。
- 过滤逻辑可配置（规则文件或函数），不硬编码。

### 3.3 存储前压缩

对超长内容（超过阈值，如 > 2000 token）做摘要压缩后再存储：

- 用轻量模型或规则做摘要（保留关键事实/决策/结论）。
- 压缩后内容仍保留原始引用的 metadata（时间、来源、标签）。
- 参考业界：Active Context Compression 报告 22.7% token 缩减且准确率持平（来源：whysogeek.com）。

### 3.4 与现有系统集成

| 现有组件                               | 改动                                              |
| -------------------------------------- | ------------------------------------------------- |
| `memory.py`（MemoryTool）              | save 增加过滤/压缩；枚举扩展；retrieve 支持新类型 |
| `smart_retrieval.py`（SmartRetriever） | 支持程序性记忆按任务类型匹配、情景记忆按查询匹配  |
| `globals.py`（短期记忆）               | 不变                                              |
| 前端/工具描述                          | 更新 memory 工具 description                      |

## 4. 实施步骤

1. **枚举与数据模型扩展**：`memory.py` 增加 procedural/episodic 类型，存储结构加 `importance`、`source` 字段。
2. **选择性存储过滤器**：实现启发式价值过滤 + `importance` 参数。
3. **压缩器**：实现摘要压缩（可先用规则/轻量模型，后续可换）。
4. **检索增强**：SmartRetriever 增加程序性（按任务类型）与情景（按查询）检索分支。
5. **工具描述更新**：memory 工具 description 说明新类型与过滤行为。
6. **测试**：新增 save 过滤/压缩、新类型检索的单测。

## 5. 风险与限制

- **误过滤**：启发式可能误删有价值信息 → 提供 `importance` 显式标注兜底，过滤逻辑可配置。
- **压缩失真**：摘要可能丢细节 → 保留原始 metadata，必要时可查原文。
- **向后兼容**：现有调用不传 importance 也能工作（走启发式默认）。
- **性能**：压缩增加 save 延迟 → 可用异步/后台压缩。

## 6. 验证方式

- 单测：过滤（高/低价值内容）、压缩（超长内容）、新类型检索（程序性按任务类型、情景按查询）。
- 集成：跑一次真实对话，观察记忆库内容质量与检索命中。
- 回归：现有 memory 相关测试全通过。

## 7. 影响面

- 主要改动：`memory.py`、`smart_retrieval.py`。
- 影响：记忆系统内部，向后兼容，不破坏现有 Agent 行为（默认开启过滤，但可关闭）。

# 使用默认配置和项目配置的合并规则

## 使用场景

当你希望保留自己的全局默认设置，同时又想让某个项目自动覆盖其中一部分行为时，可以使用默认配置与项目配置的合并方式。

## 操作步骤

1. 先在自己的用户目录准备全局配置文件 `~/.jarvis/config.yaml`。
2. 如果某个项目需要单独配置，在该项目目录或它的上层目录中放置 `.jarvis/config.yaml`。
3. 进入项目目录后再启动 Jarvis，不额外指定 `--config`。
4. 系统启动时会先读取你的全局配置，再继续查找当前目录到上层目录中的项目配置，并把更靠近当前项目的配置覆盖到前面的结果上。

## 你会看到的提示与反馈

- 如果 `~/.jarvis/config.yaml` 不存在，系统不会直接静默跳过，而是进入首次配置流程。
- 如果当前工作目录及其父目录中存在多个 `.jarvis/config.yaml`，系统会自动合并它们，不需要你手动逐个加载。
- 更靠近当前项目的配置会覆盖更上层目录和全局配置中的同名设置。
- 配置文件格式损坏时，系统会提示：`❌ 加载配置文件失败`，并可能继续询问是否删除损坏文件并重新配置。

## 注意事项

- 只有在你没有显式使用 `-f` 或 `--config` 时，系统才会按这套默认合并规则加载配置。
- 项目配置适合放项目专属设置，不适合把个人密钥、个人偏好散落到多个仓库里。
- 系统会从当前目录逐层向上查找项目配置，因此同一个项目里最好提前约定配置应该放在哪一层，避免覆盖关系不清楚。

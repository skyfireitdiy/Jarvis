# 配置结构化评估模型

## 使用场景

Jarvis 中有不少"让模型做判断"的场景，例如从一批候选规则里挑出与当前任务最匹配的几条、给待安装的技能打分、判断某段逻辑能否替换成现成的 Rust 库等。

这些场景默认使用模型组中的 Normal 模型，并依赖提示词约定 + 正则解析来拿到结果。如果你希望这类判断更稳定、更省成本，或者想专门用一个擅长结构化输出的模型（例如 Jev / TypeSafe System One）来做评估，可以在模型组中额外配置一个**结构化评估模型**。

配置后，这些决策场景会自动改用该模型；**不配置时行为与现在完全一致**，不会报错，也不会改变任何默认流程。

## 配置方式

结构化评估模型通过模型组中的 `eval_llm` 引用指定，写法与 `normal_llm` / `cheap_llm` / `smart_llm` 完全一致。

### 1. 在 `llms` 中定义评估模型

```json
{
  "llms": {
    "my_normal": {
      "platform": "openai",
      "model": "gpt-5"
    },
    "my_eval": {
      "platform": "jev",
      "model": "systemone",
      "max_input_token_count": 200000,
      "llm_config": {
        "typesafe_api_key": "你的 API Key"
      }
    }
  }
}
```

### 2. 在模型组中引用它

```json
{
  "llm_group": "default",
  "llm_groups": {
    "default": {
      "normal_llm": "my_normal",
      "eval_llm": "my_eval"
    }
  }
}
```

要点：

- `eval_llm` 是**可选**的，不写就是不启用结构化评估模型。
- 留空字符串（`""`）等同于不配置。
- 与其它引用一样，`eval_llm` 的值必须是 `llms` 中已存在的名称，否则启动时会报错。
- 和 `normal_llm` 等一样，**不能**在 `llm_groups` 里直接写 `eval_platform` / `eval_model` / `eval_max_input_token_count`，只能通过 `eval_llm` 引用。

## 未配置时的行为

未配置 `eval_llm` 时：

- 所有决策场景继续走各自原有的流程（通常是 Normal 模型）。
- 不会创建任何额外的模型实例，没有额外开销。
- 已有的 `normal_llm` / `cheap_llm` / `smart_llm` 配置不受任何影响。

## 配置后的行为

配置了 `eval_llm` 时：

- 决策场景优先使用评估模型。
- 如果评估模型调用失败、返回为空，或返回内容无法解析成预期格式，系统会**自动回退**到原有流程，并在终端给出 `⚠️` 提示，不会中断任务。

## 你会看到的提示与反馈

- 回退时你会看到类似：`⚠️  结构化评估模型调用失败，回退现有流程: ...`
- 未配置时不会有任何相关提示，与之前的使用体验一致。

## 常见问题

**问：配置后 Normal 模型还会被用到吗？**

会。评估模型只接管"做判断"的场景，主对话、代码生成等仍使用 Normal / Smart 模型。

**问：评估模型可以用和 Normal 相同的模型吗？**

可以。`eval_llm` 引用任意已定义的 LLM 配置，包括与 `normal_llm` 指向同一个。

**问：评估模型返回格式不对会怎样？**

系统会回退到原有流程，任务继续执行，只是这次判断没有用评估模型。

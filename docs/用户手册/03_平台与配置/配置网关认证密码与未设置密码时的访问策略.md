# 配置网关认证密码与未设置密码时的访问策略

## 使用场景

Jarvis Web Gateway 采用**用户名 + 密码**的账号体系进行认证。首次启动时会自动创建 `admin` 管理员账号，其初始密码来自环境变量 `JARVIS_ADMIN_PASSWORD`。如果你希望自定义初始密码、了解未设置密码时的行为，或管理多个用户，可以参考本文。

## 操作步骤

### 1. 设置 admin 初始密码

在启动 Web Gateway 服务前，先设置环境变量：

```bash
export JARVIS_ADMIN_PASSWORD='your-strong-password'
```

然后启动服务（例如 `jarvis-service run` 或对应的 systemd/docker 服务）。

### 2. 首次登录

1. 打开 Web 界面，在连接弹窗中填写：
   - 用户名：`admin`
   - 密码：上面设置的 `JARVIS_ADMIN_PASSWORD`
   - 网关地址：`ws://当前域名:8000` 或 `wss://example.com:8000`
2. 登录成功后即可进入主界面。
3. **首次登录后建议立即修改 admin 密码**：在「设置 → 修改密码」中修改；管理员也可在顶栏「管理 → 用户管理」中重置任意用户密码。

### 3. 管理多用户（可选）

管理员可在顶栏「管理 → 用户管理」中：

- 创建新用户（可指定是否为管理员）
- 为用户分配权限组
- 重置用户密码
- 编辑或删除用户

## 未设置密码时的行为

- 如果启动时**没有设置** `JARVIS_ADMIN_PASSWORD`，系统会**自动生成一个随机密码**，并打印到服务日志中。
- 查看方式（以 systemd 用户服务为例）：

  ```bash
  journalctl --user -u jarvis-master -f
  ```

- 日志中会看到类似提示：`No JARVIS_ADMIN_PASSWORD set, generated random admin password: xxxxxxxx`，其中 `xxxxxxxx` 就是本次的 admin 初始密码。

## 你会看到的提示与反馈

- 登录时如果用户名或密码错误，接口会返回认证失败提示。
- 登录成功后，前端会保存会话凭证，后续请求自动带上认证信息。
- 登录失败会记录失败次数（`login_fail_count`），但系统**不会自动锁定**账号；如需锁定，管理员可在「管理 → 用户管理」中把该用户状态手动改为「锁定」或「禁用」。

## 注意事项

- 认证方式是基于 `users.json` 的用户账号体系（存储于 Jarvis 数据目录的 `auth/` 下），**不是**配置文件里的某个开关。
- `JARVIS_ADMIN_PASSWORD` 只在**首次创建 admin 用户**时生效；如果 admin 已存在，修改环境变量不会自动覆盖已有密码，请通过「修改密码」或「用户管理」重置。
- 请使用强密码，并妥善保管；不要在生产环境使用默认/随机密码长期运行。
- 多用户、权限组等能力由 Web 界面「管理」入口提供，具体以当前版本界面为准。

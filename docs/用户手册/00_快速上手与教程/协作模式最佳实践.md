# 协作模式最佳实践

## 使用场景

当你有多个 Agent 需要**互相沟通、协同推进**（而非按固定 DAG 编排），或需要 Agent 与人类在同一个会话里协作时，用 Jarvis 的协作机制：

- **群组（Group）**：一组 Agent 的集合，成员可以互相发消息广播。
- **聊天室（Chat Room）**：Web 界面里的实时会话，Agent 与人类可同处一室。
- **私聊（Private Message）**：Agent 之间点对点发消息。

这些能力都由内置工具 **`gateway_manager`** 提供，底层经 Web Gateway 转发。

## 前置条件

- 已启动 Web Gateway（`jwg`，默认端口 8000）。
- Agent 已连接网关（在 Web 界面创建，或带 `--web-gateway` 启动）。
- 群组 / 聊天室操作需要 Agent 有 `agent_id`（由网关的 AgentManager 分配）。

## 操作步骤

### 一、群组协作

#### 1. 创建群组

```text
gateway_manager(
  action="create_group",
  group_name="重构小组",
  group_description="负责模块重构的协作组"
)
```

#### 2. 查看群组

```text
gateway_manager(action="list_groups")
gateway_manager(action="get_group", group_id="<group_id>")
```

#### 3. 加入 / 退出群组

Agent 用 `join_group` 加入（以自身 `agent_id` 身份）：

```text
gateway_manager(action="join_group", group_id="<group_id>")
gateway_manager(action="leave_group", group_id="<group_id>")
```

#### 4. 发送群组消息

```text
gateway_manager(
  action="send_group_message",
  group_id="<group_id>",
  message="我已完成 planner 阶段的产出，产物在 .df/plan.md"
)
```

发送后，工具会在消息末尾自动附上"如何回复"的提示，方便其他成员回帖。若发送者想等待回复，可在输出后加 `<Wait>`。

### 二、聊天室协作（Agent 与人类同处一室）

#### 1. 查看聊天室与在线成员

```text
gateway_manager(action="chat_list_rooms")
gateway_manager(action="chat_get_online_clients")
gateway_manager(action="list_sessions")
gateway_manager(action="chat_get_room_members", room_id="<room_id>")
```

#### 2. 发消息到聊天室

```text
gateway_manager(
  action="chat_send_room_message",
  room_id="<room_id>",
  message="当前流水线已跑到 validator 阶段，等待审批"
)
```

消息会自动加上 `[Agent名字]` 前缀，并以属主身份发送，人类在 Web 界面即可看到。

### 三、Agent 之间私聊

```text
gateway_manager(
  action="chat_send_private_message",
  receiver_id="<client_id 或 user_id>",
  message="请把 .df/report.json 的 pass_rate 发我"
)
```

同样自动加 `[Agent名字]` 前缀。

### 四、点对点派发任务（不经过群组）

如果只是想"让某个 Agent 做一件事"，直接用 `send_to_agent`，并可**同步等待**其完成：

```text
gateway_manager(
  action="send_to_agent",
  agent_id="<agent_id>",
  message="统计 tests/ 下的测试数量",
  wait=true,
  status_file="/tmp/agent_done.json"
)
```

- `wait=true`：轮询 `status_file` 判断完成（Agent 完成后写入 `{"status": "completed"|"failed"}`）。
- 不传 `status_file` 时兜底轮询 Agent `/status` 的 `execution_status`（不完全可靠，建议显式传 `status_file`）。
- `wait` 默认 `false`（异步 fire-and-forget）。

## 你会看到的提示与反馈

- **群组消息**：发送成功后返回群组与消息内容，并附"回复此群组消息请用 …"的提示。
- **聊天室消息**：返回 `room_id` 与带前缀的消息内容。
- **`send_to_agent(wait=true)`**：阻塞直到目标 Agent 完成或超时，返回完成状态。
- **Web 界面**：聊天室消息实时显示，带 `[Agent名字]` 前缀区分发言者。

## 最佳实践

### 1. 先选对协作形态

| 需求 | 用什么 |
| --- | --- |
| 有明确阶段依赖、要产出物传递 | `pipeline_runner` 编排（见 [多 Agent 编排](多 Agent 编排：用%20pipeline_runner%20驱动流水线.md)） |
| 多个 Agent 平等讨论 / 广播 | 群组（`create_group` + `send_group_message`） |
| Agent 与人类实时协同 | 聊天室（`chat_send_room_message`） |
| 一对一派活并等结果 | `send_to_agent(wait=true, status_file=...)` |

### 2. 明确"谁是协调者"

群组协作容易变成"人人发言、无人拍板"。建议指定一个协调 Agent（类似 sw-controller），由它汇总各成员产出、决定下一步，其他成员只汇报自己那份。

### 3. 用 `status_file` 做完成信号

`send_to_agent(wait=true)` 依赖完成信号判断结束。让目标 Agent 在任务结束时写 `status_file`，比轮询 `/status` 可靠得多。

### 4. 消息尽量结构化

协作消息里带上"阶段名 / 产物路径 / 结论"，便于其他 Agent 直接引用，减少来回澄清。

### 5. 隔离敏感信息

群组 / 聊天室是广播语义，不要把密钥、隐私数据发进去；需要点对点传敏感内容时用私聊。

## 注意事项

- 群组 / 聊天室操作需要 Agent 已有 `agent_id`；未连接网关时 `join_group` / `send_group_message` 会报 `agent_id is not available`。
- `send_group_message` 需要 `group_id` 与 `message` 都非空。
- `chat_send_room_message` 需要 `room_id` 与 `message` 都非空。
- `chat_send_private_message` 的 `receiver_id` 可以是 `client_id` 或 `user_id`。
- `send_to_agent` 的 `agent_id` 支持单个字符串或数组。
- 示例中的 action 与参数均来自 `src/jarvis/jarvis_tools/gateway_manager.py`，可直接使用。

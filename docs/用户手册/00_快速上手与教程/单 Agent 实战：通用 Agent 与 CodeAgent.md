# 单 Agent 实战：通用 Agent 与 CodeAgent

## 使用场景

你已按 [快速上手：从零安装到首次运行](快速上手：从零安装到首次运行.md) 装好 Jarvis，现在想真正用它干活。Jarvis 提供两类主力 Agent：

- **通用 Agent（`jvs`）**：面向"问答 + 工具调用"，适合调研、检索、读写文件、跑命令、做分析等开放任务。
- **CodeAgent（`jca`）**：面向"改代码"，在通用能力之上叠加代码定位、修改、静态检查 / 构建验证、自动提交等工程化流程。

本篇教你分别把它们用起来，并给出选择建议。

## 操作步骤

### 一、通用 Agent（`jvs`）

#### 1. 交互式对话

```bash
jvs
```

进入后直接输入任务，回车发送。例如：

```text
读一下当前目录的 README.md，用三句话总结这个项目是做什么的。
```

Agent 会展示思考过程与工具调用（读文件、执行命令等），并在需要确认时询问你。

#### 2. 一次性执行任务

不进入交互界面，直接把任务作为参数传入：

```bash
jvs -T "统计当前目录下各语言的代码行数，按从多到少排序"
```

常用参数：

| 参数 | 说明 |
| --- | --- |
| `-T` / `--task` | 直接指定任务描述 |
| `--task-file` | 从文件读取任务描述（与 `-T` 互斥） |
| `-g` / `--llm-group` | 指定模型组，覆盖配置 |
| `-G` / `--tool-group` | 指定工具组，覆盖配置 |
| `-f` / `--config` | 指定配置文件路径 |
| `--append-tools` | 追加工具，逗号分隔 |
| `-q` / `--quick` | 极速模式：跳过任务分类、规则自动加载等 |
| `-Q` / `--quiet` | 安静模式：抑制控制台输出 |

> 完整的通用 Agent 能力（会话恢复、规则加载、非交互模式等）见 `docs/用户手册/01_通用_agent/` 目录。

### 二、CodeAgent（`jca`）

#### 1. 在 Git 仓库中交互式改代码

```bash
cd /path/to/your/repo
jca
```

输入一个明确的小任务，例如：

```text
给 README.md 顶部的项目名后补一句一句话简介。
```

CodeAgent 会：定位文件 → 修改 → 展示 diff 预览 → 按配置执行静态检查 / 构建验证 → 生成提交。**必须在 Git 仓库内运行**（它会检查 `git rev-parse --is-inside-work-tree`）。

#### 2. 非交互式执行（适合脚本 / CI）

```bash
jca -n -T "修复 src/utils.py 中 parse_date 的空指针问题"
```

`-n` / `--non-interactive` 表示用户无法交互，脚本执行超时限制为 5 分钟。

#### 3. 用 worktree 隔离开发

```bash
jca -w
```

`-w` / `--worktree` 会在独立分支 / 工作树上开发，不污染当前工作区，适合"不确定要不要采纳"的改动。

#### 4. 常用参数

| 参数 | 说明 |
| --- | --- |
| `-T` / `--task` | 任务描述 |
| `--task-file` | 从文件读取任务 |
| `-n` / `--non-interactive` | 非交互模式（必须配合 `-T`） |
| `-w` / `--worktree` | git worktree 隔离开发 |
| `-r` / `--restore` | 交互式选择恢复会话 |
| `-R` / `--restore-session` | 从指定会话文件恢复 |
| `--rule-names` | 指定规则名列表（逗号分隔），从 `rules.yaml` 读取 |
| `--disable-review` | 关闭改码后的自动代码审查 |
| `--review-max-iterations` | 代码审查最大迭代次数（0 表示不限） |
| `--prefix` / `--suffix` | 提交信息的前缀 / 后缀 |
| `-d` / `--dispatch` | 派发任务到新的 tmux 窗口执行（需在 tmux 中） |
| `-q` / `--quick` | 极速模式 |
| `-Q` / `--quiet` | 安静模式 |

### 三、怎么选

| 你的目标 | 用哪个 |
| --- | --- |
| 问问题、查资料、跑命令、做分析 | `jvs` |
| 修改代码、修 bug、加功能、写测试 | `jca` |
| 需要自动提交 / 静态检查 / 构建验证 | `jca` |
| 需要隔离分支试改 | `jca -w` |

## 你会看到的提示与反馈

- **思考与工具调用**：Agent 会打印它调用了哪些工具、参数是什么、结果如何。
- **确认请求**：涉及写文件、执行命令等操作时，可能弹出确认（取决于配置），需要你回复是否执行。
- **diff 预览与提交**：`jca` 在改完后展示 diff，并按配置生成提交（提交信息由模型生成，可加 `--prefix`/`--suffix`）。
- **代码审查**：默认改码后会做一轮自动审查，可用 `--disable-review` 关闭。

## 注意事项

- `jca` 需要当前目录是 Git 仓库；不在仓库内会直接报错。
- 非交互模式（`-n`）必须用 `-T` 或 `--task-file` 提供任务，因为多行输入不可用。
- `-T` 与 `--task-file` 不能同时使用。
- 会话恢复前会检查 Git commit 是否一致、历史是否超出当前模型 token 限制，按提示选择即可。
- 示例中的命令均来自仓库真实 CLI 定义（`src/jarvis/jarvis_code_agent/code_agent.py`、`src/jarvis/jarvis_agent/jarvis.py`），可直接运行。

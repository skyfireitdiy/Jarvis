# 启动 Web Gateway 服务

## 使用场景

当你希望通过浏览器使用 Jarvis 的 Web 界面，而不是只在终端里操作时，需要先启动 Web Gateway 服务。这个服务负责提供浏览器访问入口，并转发后续的网页连接、认证和操作请求。

## 操作步骤

1. 在终端中输入下面的命令，然后按回车：`jarvis-service run`
2. 如需使用默认配置，直接运行即可；默认会监听本地地址 `127.0.0.1` 和端口 `8000`。
3. 如果你想改监听地址或端口，可以使用类似命令：`jarvis-service run --host 0.0.0.0 --port 9000`
4. 如果你希望浏览器连接前需要登录，可先通过环境变量 `JARVIS_ADMIN_PASSWORD` 设置 admin 初始密码，例如：

   ```bash
   export JARVIS_ADMIN_PASSWORD='你的密码'
   jarvis-service run
   ```

   首次启动时会自动创建 `admin` 账号，其初始密码即为此环境变量的值（未设置时会生成随机密码并打印到日志，详见「配置网关认证密码与未设置密码时的访问策略」）。

5. 提交命令后，保持这个终端窗口不要关闭，让 Web Gateway 服务持续运行。
6. 服务启动后，再到浏览器中访问对应的 Web 页面，使用用户名 + 密码登录并连接。

## 你会看到的提示与反馈

- 启动时，终端会显示：
  - Gateway 监听地址与端口
  - Frontend 监听地址与端口
  - 当前 Node 模式

- 启动成功后，服务会持续运行在当前终端，不会立即退出。
- 浏览器连接时，需要输入用户名（首次为 `admin`）与密码完成登录。

## Node 模式补充说明

如果你正在使用多节点部署，可以在启动 Gateway 时增加 `--node-mode` 参数，使当前 Gateway 以主节点或子节点身份运行。

### 作为主节点启动

- 示例命令：`jarvis-service run --node-mode master`
- 适用场景：当前节点负责对外提供统一入口，浏览器、Web 客户端都连接到这个主节点。
- 启动后，主节点除了管理本地 Agent，还会维护已接入的子节点信息。

### 作为子节点启动

- 示例命令：`jarvis-service run --node-mode child --node-id worker-01 --master-url ws://master-host:8000 --node-secret your_secret`
- 适用场景：当前节点不直接作为统一访问入口，而是接入某个主节点，负责承载远端 Agent。
- 子节点启动后，会与主节点建立长期连接，并由主节点统一对外暴露 Agent 能力。

### 使用建议

- 单节点部署时，可以继续按原来的方式启动；如果当前版本要求显式声明模式，则使用 `--node-mode master`。
- 多节点部署时，建议先启动主节点，再启动子节点并确认子节点已成功接入。
- 浏览器、Web 客户端通常连接主节点，而不是直接连接子节点。

## 注意事项

- 这是终端中的启动步骤，不是浏览器页面里的操作。
- 未设置 `JARVIS_ADMIN_PASSWORD` 时，系统会生成随机 admin 密码并打印到服务日志，浏览器登录时需使用该密码；建议首次登录后立即修改。
- Web Gateway 运行期间需要保持终端进程存活；如果你关闭了启动它的终端，浏览器连接通常也会中断。
- 如果你只监听 `127.0.0.1`，通常只适合本机访问。
- 在 node 模式下，主节点与子节点之间还需要满足网络可达；如果子节点无法接入主节点，浏览器侧将看不到对应节点上的 Agent。
